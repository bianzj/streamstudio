# 开发更新与用户发布

用户于 2026-11-01 明确区分两类交付，适用于当前各软件项目：

- 日常开发：代码、测试代码、最小验证材料和开发文档保留在 C 盘项目，通过 GitHub 提交与推送更新。小修改完成相应测试级别检查即可，不自动增加版本号、构建安装包或创建 GitHub Release。
- 用户发布：安装包、可实际运行的案例、必要用户说明和文件清单放在 D:/发布/<项目>/<版本>。同一项目的安装包与案例在一个发布目录内。用户明确要求发布、或明确安排发布版本时再执行发布流程。
- 研究数据、历史运行、SCOPE 对比、维护记录与开发归档保留在相应研究/归档目录，不自动混入用户包。
- 开发文档在 C 盘维护；供用户阅读的手册可以随发布包提供副本。测试脚本、验收摘要在 C 盘项目；原始测试日志和输出在项目忽略目录 .test/，不随用户包分发。
- 可行案例必须具备完整输入、相对路径、操作说明和明确的运行核验范围。文件齐全或哈希相同只能证明文件完整性，不能替代运行检查或科学精度验证。

Stream Studio 开发入口：C:/work/streamstudio。用户交付入口：D:/发布/streamstudio/2.0.1。本次只优化现有 2.0.1 的本机交付资料，保留原安装器，不创建新软件版本、不改动已发布 GitHub Release。
