# STREAM 统一工作流：一张表单，温度处切换

状态：重设计草案（2026-10-27），未改代码。若采纳，取代 `stream-simple-modes.md` 的“RT/EB 各一套”和 `stream-assimilation-ui.md` 的“目标×观测矩阵”。

## 1. 现在的问题

同一件事被拆成了好几处入口，用户要先理解模式才能填参数：

| 位置 | 现在 | 问题 |
| --- | --- | --- |
| 菜单“解决方案” | 像元辐射传输 / 像元能量平衡 两项 | 像两个独立方案 |
| 工作台顶部 | RT / EB 两张模式卡 | 和“温度来源”重复 |
| “目标与观测”组 | 5 个目标 × 5 个观测多选 + 5 个预设 + 4 种行为矩阵 | 反演引擎没接入，却最先出现；LAI/土壤水分/发射率本轮也不反演 |
| “温度来源”组 | RT 子面板 / EB 子面板 | 与顶部模式卡联动 |
| 土壤水分 | 地表输入一处 + EB 里“ERA5 / 地表输入”切换一处，互相隐藏 | 同一个量两个开关 |
| 热红外波段 | 和温度来源分在两个组 | 温度只在热红外启用时有用，却分开放 |

## 2. 核心思路

**所有输入只有一套，唯一的分叉是“组分温度从哪来”。** 正向、能量平衡、反演都只是这个问题的三个答案：

| 温度来源 | 用户心里的问题 | 额外输入 | 内部 mode |
| --- | --- | --- | --- |
| **给定** | 我知道温度 | 四组分常数/栅格，或 4 波段文件 | `rt` |
| **能量平衡** | 用气象算出温度 | ERA5 数据包 | `eb` |
| **由观测反演** | 用卫星亮温反推温度 | 观测亮温文件（+ 可选先验） | `invert`（新增） |

不再有“模拟模式”“作业模式”“目标变量”“同化观测”这些概念。

## 3. 界面

```
影像模拟输入
  ▸ 位置与过境时刻
  ▸ 观测几何              VZA / VAA
  ▸ 地表输入              地类、LAI、土壤水分、DEM
  ▸ 光学波段        [开关]
  ▾ 热红外          [开关]
      传感器  [Landsat 8/9 TIRS ▾]   波段表
      组分温度  ( 给定 | 能量平衡 | 由观测反演 )
        ├ 给定：      四组分 Tss/Tsh/Tls/Tlh（常数/栅格）或 组分温度文件
        ├ 能量平衡：  ERA5 数据包 ▾   [ ] DEM 高程订正
        └ 由观测反演：观测亮温文件 ______ [浏览]   （波段顺序同上表）
                      先验  ( 自动 | 能量平衡 )
                      ▸ 高级：观测误差 0.5 K、先验误差 8 K、迭代上限
  ▸ 计算范围
[ 运行 ]
```

要点：

1. **温度归到“热红外”组里**。关掉热红外就不会问温度；只做光学 BRF 时界面最短。
2. **三选一的分段按钮**，切换只换下面一小块，其余输入全部保留、共用。
3. **删掉顶部 RT/EB 模式卡和“目标与观测”组**。
4. **土壤水分只有一个字段**（地表输入里）：填了就用；留空时能量平衡用 ERA5 swvl1，其他情况取 0.25。不再有 ERA5/地表输入切换。
5. **反演不需要选目标**：本轮反演对象只有 LST/LSCT（见 `stream-lst-lsct-requirements.md`），总是输出两者，并附不确定性与 QA。单视角时 LSCT 的 QA 标为“先验主导”，不隐藏结果，也不让用户自己判断能不能反演。
6. **先验默认“自动”**：用观测亮温粗估的等效温度作四组分先验，不要求 ERA5；选“能量平衡”时复用上面同一个 ERA5 数据包选择器，先跑 EB 再用它的结果作先验。
7. 运行按钮文字始终是“运行”；日志首行写明“温度来源：给定 / 能量平衡 / 由观测反演”。

菜单“解析解决方案”下两项合并为一项 **像元模拟（Pixel）**；`new-rt`/`new-eb`/`mode-rt`/`mode-eb` 命令保留为兼容别名，只预选温度来源。

## 4. 输出

一个结果页，按温度来源多出几类产品，不分页面：

| 温度来源 | 产品 |
| --- | --- |
| 共有 | 光学反射率、亮温、方向温度、组分温度、太阳几何 |
| 能量平衡 | + 能量通量、ERA5 驱动 |
| 由观测反演 | + `lst.tif`、`lsct.tif`、各自 1σ、观测残差、QA |

## 5. 工程与配置（向后兼容）

`scene.temperature` 位置不变，只扩展：

```jsonc
"temperature": {
  "mode": "rt" | "eb" | "invert",
  "components": { ... },               // rt 用
  "era5": { "pack": "..." },           // eb 用；invert + 先验=能量平衡 也用
  "observation": { "file": "...", "sigma": 0.5 },   // invert 用，波段顺序 = thermal.bands
  "prior": { "source": "auto" | "eb", "sigma": 8 }, // invert 用
  "elevationCorrection": true
}
```

- 旧工程 `rt`/`eb` 原样可读；
- `scene.assimilation` 读入时忽略，保存时不再写；
- `temperature.soilMoisture.source`：读入时若为 `era5`，就把地表土壤水分视为留空（行为不变）；保存时不再写；
- 运行端：`rt`/`eb` 仍是 `stream.exe run`；`invert` 由服务端编排：（先验=能量平衡时先跑 EB）→ 正向算子 → 反演，结果写进同一个运行目录。
