# Stream Studio 模型使用手册

软件版本：2.0.0
工程格式：`schemaVersion = 6`
更新日期：2026-10-30

## 1. 软件用途

Stream Studio 用于在三维地表场景中模拟光学与热红外遥感信号。当前版本集成面元辐射传输、体元辐射传输、面元能量平衡、体元能量平衡和简单光线追踪，并提供 DEM、OBJ、参数化几何、水体、火焰、局部雾介质、大气查找表及简化流体模块。

模型适用于以下任务：

- 生成多波段、多角度光学或热红外图像；
- 模拟地表温度的时间变化与方向性；
- 比较面元和体元表达造成的模拟差异；
- 分析建筑、植被、土壤、水体及火点对遥感信号的影响；
- 输出辐射、能量和流体过程数据；
- 将模拟结果与观测图像进行变化和散点分析。

Stream Studio 是研究型正向模型。输入结构、材质和气象条件的质量会直接影响结果，不应把默认参数视为任意场景的真实参数。

## 2. 安装、构建与启动

### 2.1 项目目录

默认项目根目录为：

```text
C:\work\streamstudio
```

主要目录如下：

```text
streamstudio/
├─ src/renderer/               GUI 源码
├─ gui/                        GUI 编译结果
├─ assets/                     内置 OBJ、DEM、光谱和大气数据
├─ docs/                       使用手册与理论手册
├─ build/histream/             CMake 中间文件
├─ models/histream/            HiStream 源码、Shader 和属性数据
├─ models/bin_x64/Release/     Release 引擎
├─ models/bin_x64/Debug/       Debug 引擎
├─ runtime/                    运行期文件、日志和历史归档
├─ tools/                      构建和资源脚本
├─ server.mjs                 本地服务与结果转换
└─ package.json               Node.js 命令入口
```

### 2.2 安装包安装

Windows 64 位安装包为：

```text
Stream-Studio-Setup-<版本>-x64-slim.exe
```

双击安装后可选择安装目录；安装器会创建桌面快捷方式和开始菜单快捷方式。安装内容包括 GUI、`histream.exe`、Release DLL 与 Shader、材质/光谱/DEM/OBJ/大气库，以及本使用手册和理论手册。软件主窗体默认占满系统工作区高度，并避开 Windows 任务栏。

精简安装包不包含 `.pdb`、`.lib`、源码目录、名称符合 `_..._source` 的 OBJ 源数据目录、示例工程的 `output` 运行结果目录，以及单个大于 15 MiB 的 OBJ。作物模型只保留成熟玉米、小麦、水稻和向日葵四个常用低模。若某个 RAMI 场景依赖被排除的大 OBJ，该不完整场景也不会打包。Electron 运行语言仅保留 `zh-CN` 与 `en-US`。

运行时默认调用安装目录中的内置引擎 `engine\histream.exe`。如需改用其他引擎，须先把其完整路径加入环境变量 `STREAM_STUDIO_ENGINE_ALLOWLIST`（多个路径以分号分隔）并重启 Stream Studio，否则运行会被拒绝；在“引擎”对话框中留空即恢复内置引擎。

### 2.3 源码构建

在 PowerShell 中执行：

```powershell
cd C:\work\streamstudio
npm install
npm run build:all
```

可单独构建：

```powershell
npm run build:gui
npm run build:engine
```

GUI 输出到 `gui`，CMake 中间文件输出到 `build/histream`，引擎输出到 `models/bin_x64/Release`。引擎构建需要 Visual Studio、Vulkan SDK 和 vcpkg；构建脚本优先读取 `VCPKG_ROOT`，未设置时查找项目同级的 `vcpkg`。

### 2.4 源码启动

生产模式：

```powershell
npm start
```

开发模式：

```powershell
npm run dev
```

浏览器地址：

```text

```

## 3. 工程结构

### 3.1 新建工程

点击顶部“新建工程”，选择保存目录并填写工程名称。系统创建：

```text
project-name/
├─ project.json       唯一工程入口
├─ models/            工程 OBJ
├─ positions/         实例位置
├─ spectral/          自定义波谱
├─ meteorology/       气象驱动
├─ terrain/           DEM
└─ output/            模拟结果
```

工程只使用 `project.json` 作为配置和运行入口，正式链路为“GUI → `project.json` → Node 本地服务 → `histream.exe`”。XML 仅保留旧版本兼容代码，不参与当前正式运行，也不会在运行时生成供引擎传递的 XML。

### 3.2 打开、保存与迁移

“打开工程”应选择工程目录内的 `project.json`。相对路径以该文件所在目录为基准；工程目录内的文件会尽量保存为相对路径，便于整体移动工程。

旧版本字段在打开时会经过标准化，保存后写为当前 `schemaVersion = 6` 格式；当前程序仅接受 schema 1–6。建议迁移前备份原工程。顶部“保存”覆盖当前工程，“另存为”将当前配置和工程内依赖复制到新位置并切换到新工程。

### 3.2.1 保存时同步 project.usd

每次“保存”或“另存为”都会在 `project.json` 旁同步写出 `project.usd`（OpenUSD 文本格式），可直接在 Blender 3.0+、Houdini、Maya、NVIDIA Omniverse、usdview 等软件中打开，无需单独导出。

- 坐标：`upAxis = "Y"`，单位米（`metersPerUnit = 1`），X 为北、Z 为东，与编辑器预览一致；Blender 导入时会自动转为 Z 轴向上。
- 几何：每个 OBJ 转换为 `usd/<OBJ 名>-<校验码>.usda` 原型资产，只在 OBJ 变化时重建，因此日常保存只需改写较小的 `project.usd`；原型按 OBJ 分组（`o`/`g`）拆成网格并以最低点落地。每个位置记录写为引用原型的 instanceable Xform（平移、绕 Y 旋转、缩放）。PRIM 盒体/椭球与火焰、雾介质写为 Cube/Sphere。地面为平面或按 DEM 采样（每边最多 256 格）的地形网格。
- 太阳：`/World/Sun`（DistantLight），方向由太阳天顶角和方位角确定。
- 材质：每条光谱记录生成一个 UsdPreviewSurface 预览材质（颜色仅用于显示）；光谱、热学、物化、冠层等 Stream Studio 参数以 `histream:*` 自定义属性写在网格和实例上，完整 `project.json` 保存在图层元数据 `customLayerData.histream.project` 中（旧版导出的 `streamsim:*` 属性仍可读取）。
- `usd/sync.json` 记录 Stream Studio 最后写出或载入的 USD 校验码。若 `project.usd` 已在其他软件中被修改，打开工程时会询问是否载入这些修改；不载入而直接保存时，旧文件会先备份为 `project.external-<时间>.usd` 再覆盖。
- 同步失败（例如 OBJ 缺失）不影响 `project.json` 的保存，原因写入运行日志。

### 3.2.2 直接打开 OpenUSD

“打开工程”可直接选择 `.usd`/`.usda`/`.usdc`/`.usdz`，由随引擎发布的 `histream-usd.exe`（基于官方 OpenUSD 库，支持引用、实例、多层组合）读取：

- 若该 USD 就是 Stream Studio 上次写出的文件（与 `usd/sync.json` 一致），直接打开同目录的 `project.json`。
- 否则用 USD 场景替换同目录 `project.json` 中的全部场景对象，太阳、传感器、气象、计算设置等保持不变，原文件另存为 `project.before-usd-import-<时间>.json`；同目录没有 `project.json` 时自动新建（有内嵌 Stream Studio 工程时按其恢复设置，否则用当前计算模式的默认工程）。
- 坐标：自动按 USD 的 `upAxis`（Blender 为 Z 向上）和 `metersPerUnit` 换算为 Stream Studio 的 Y 向上、米制坐标。
- 对象：实例按其原型合并为一个对象；非实例网格按所属父级 Xform 分组，几何完全相同的副本自动合并。几何写入 `models/usd-import-<时间>/`，实例位置写入 `positions/usd-import-<时间>/`。只含平移、绕竖直轴旋转和等比缩放的摆放直接成为实例记录；倾斜、镜像或非等比缩放的摆放会把变换烘焙进单独的 OBJ。
- 参数恢复顺序：网格上的 `histream:*` 属性 → USD 内嵌的 Stream Studio 工程 → USD 材质名与光谱记录同名 → 当前工程中同名对象/网格 → 按植被/非植被给默认值。载入后请在“场景对象”中检查各网格的材质。
- 名为 `Ground` 或带 `histream:role = ground` 的地面网格、guide/proxy 用途及不可见的对象不导入。

### 3.3 推荐命名

- 工程名称、对象内部名称和材质内部名称使用英文小写、数字与下划线；
- 同一工程内名称必须表达唯一含义，例如 `tree_oak`、`roof_concrete`；
- 显示名称可以使用中文；
- 文件使用小写英文和下划线，避免空格、括号及特殊符号；
- 长期保存的工程尽量使用相对路径。

## 4. 界面布局

窗口最上方是菜单栏：“项目”菜单含新建工程、打开工程、打开示例、保存和另存为；“结果”菜单含二维水平和三维立体；“分析”菜单含时间、角度、波段分析和变化分析；“解决方案”菜单含三维解决方案（面元/体元辐射传输与能量平衡、简单光线追踪）和解析解决方案（像元辐射传输、像元能量平衡，打开 STREAM 影像模拟工作台，见 5.2 节）；“帮助”菜单含理论与参考、使用手册、理论手册、快捷键和版本信息。菜单栏下方的工具栏保留语言切换、运行模拟、停止和重置。影像模拟工作台打开时，“项目”菜单中的新建、打开、保存和另存为作用于影像模拟工程。“重置”会结束当前 HiStream 三维进程、清理本次运行状态并恢复可再次启动的界面，不影响影像模拟任务；它不会删除工程输入和已经落盘的结果。

顶栏 `EN / 中文` 按钮可在程序内即时切换界面语言，默认语言为中文，并通过浏览器本地存储自动记忆上次选择。语言切换覆盖静态界面、动态属性检查器、计算模式和主要对话框；工程名、文件路径、`project.json` 原始字段及引擎日志不强制翻译。中英文名称只影响显示，不改变模式枚举、工程配置或结果数值。

左侧按任务顺序分组：

1. 计算模型；
2. 主要输入：场景、太阳与天空、传感器、场景对象、材质属性、气象驱动；
3. 备选输入：流体力学、大气影响；
4. 运行与控制：仿真模拟。

中间区域显示 Three.js 场景预览、场景范围框、坐标轴、帧率和三角形数量。预览只用于检查位置、尺度、朝向、材质纹理和外观，不等同于 HiStream 的计算网格。实例过多时 Three.js 最多抽样显示 5000 个，正式计算和结果文件仍保留全部有效实例。

右侧为当前条目的属性检查器。底部显示运行进度、已用时间、日志和结果入口。

## 5. 计算模式

| 模式 | 几何表达 | 主要用途 | 时间演化 | 当前特有功能 |
|---|---|---|---|---|
| FacetRT | 三角面元 | 高精度光学/热红外辐射传输 | 否 | 面元可见性图与辐射度求解 |
| FacetEB | 三角面元 | 面元温度与能量过程 | 是 | 面元 RT–EB 耦合 |
| VoxelRT | 体元 | 大场景快速光学/热红外模拟 | 否 | 异质性体元、火焰与雾介质 |
| Voxel RT–EB（`eVoxelEB`） | 体元 | 温度时间序列与能量过程 | 是 | 异质性体元、火焰、雾、简化流体 |
| RayTracing | 三角面元 | 简单后向光线追踪基准 | 否 | 路径追踪式成像 |

新建工程的当前默认设置为：

| 项目 | 默认值 |
|---|---|
| 计算模式 | `eVoxelEB`：体元辐射传输与能量平衡 / Voxel Radiative Transfer & Energy Balance |
| 土壤温度方法 | `soilTemperatureMethod = 2`：温度廓线传导模型 |
| 气象节点 | 界面开始节点 1、结束节点 48，实际计算区间为 `[1, 48)` |

选择建议：

- 需要保留细致表面几何时使用 FacetRT 或 FacetEB；
- 场景较大、对象较多或需要快速时间序列时优先使用 VoxelRT 或 Voxel RT–EB；
- 需要独立的光线追踪对照时使用 RayTracing；
- 同一研究比较不同模式时，应保持场景、光谱、角度、波段和输出分辨率一致。

### 5.1 1.1 版重点：异质性体元

异质性体元用于在较粗体元中保留 OBJ 的亚体元结构信息，尤其适合树冠、作物群体、建筑与植被交错以及多个对象重叠的场景。开启后，程序在正式辐射求解前完成一次结构提取：

1. 用 OBJ 三角面确定有效体元，不把完整立方体面元送入 Facet 求解器；
2. 在每个有效体元内统计真实结构密度 `rho`；
3. 沿 X/Y/Z 三个方向计算投影并集覆盖率，并反演 `CIx/CIy/CIz`；
4. 多个实例或地物在同一体元重叠时，先合并遮挡掩膜，再按三轴遮挡贡献保留最重要的两个类别；
5. 将结构描述符和综合后的光谱、温度、物化属性送入 VoxelRT/VoxelEB。

运行阶段根据射线方向组合三轴聚集指数，使用 `rho × G × CI(direction)` 计算路径消光，并作用于太阳直射、天空漫射、多次散射、热红外发射与传感器成像。VoxelEB 继续在此基础上计算净辐射、显热、潜热、土壤热通量、温度以及植被 GPP/NPP。

推荐操作：

- 在“仿真控制 → 异质性体元”中勾选该功能，仅 VoxelRT/VoxelEB 生效；
- 先用较大体元完成试算，再逐步减小体元并比较亮温、反射率和组分温度是否稳定；
- 查看日志中的 `Heterogeneous Mesh voxels`、网格尺寸、有效体元数、平均密度和提取耗时；
- 对均匀背景、简单实体或只要求快速预览的任务可关闭，以省去三角面投影统计时间；
- 一个粗体元内若有三个以上贡献接近的类别，应减小体元，避免较弱类别被舍弃。

该功能增加的是一次性体元化预处理，不会在每条射线路径上反复展开原始 OBJ，也不会为每个体元建立完整六面立方体。其目标是在面元细节与均质体元效率之间取得可解释的折中。

### 5.2 遥感影像模拟（STREAM）

上面五种模式都针对三维场景（米级对象）。菜单栏“遥感影像模拟”打开 STREAM 影像模拟工作台，用于卫星影像尺度：输入地表结构、观测几何、过境时刻和温度来源，输出整景光学反射率与热红外亮温。它调用随软件分发的 `stream.exe`，与三维工程、三维任务队列和三维结果完全独立，可以和 HiStream 模拟同时运行（CPU 线程可在“计算范围 → 线程数”中限制）。

**一次模拟对应一个过境时刻（UTC）。** 组分温度有两种来源：

| 模式 | 适用 | 输入 |
|---|---|---|
| RT · 已知组分温度 | 已有组分温度（实测、反演或此前 EB 运行结果） | 四个组分温度 Tss/Tsh/Tcs/Tch 分别给常数、单波段栅格或 24 波段逐小时栅格（按过境时刻 UTC 小时自动选波段）；或一个 4 波段组分温度文件（如 EB 输出的 `components.tif`） |
| EB · ERA5 能量平衡 | 温度未知 | 一个登记好的 ERA5 数据包（一天到一年均可）。只算过境当天：从当日 00 UTC 起逐整点求解四组分能量平衡，最后一个时次正好是过境时刻；土壤与叶片初温取首日平均气温，土壤热历史与 2 m 土柱自洽推进（与 TIRTEB 一致） |

地表输入（除地表类型外都可以是同网格栅格或常数）：

| 输入 | 要求 | 作用 |
|---|---|---|
| 地表类型 IGBP | 必填，单波段栅格，0–17 | 决定模拟网格和坐标系；按地类读取 `stream-defined/classes.json` 中的冠层、叶片、光合与地面参数。17 水体、18/255 填充值不输出光学反射率；EB 中水体温度取 ERA5 `skt`；城市（13）按不透水地面 + 绿地冠层的四组分处理 |
| LAI | 必填，m²/m² | 冠层结构 |
| 土壤水分 SM | 可选，m³/m³，默认 0.25 | BSM 土壤光谱与土壤热红外发射率（含水量越高发射率越高，见 13.3）；只有把土壤阻抗方法设为 `sellers` 时才参与土壤蒸发阻抗（默认常数 200 s m⁻¹）。EB 可改为取 ERA5 `swvl1`（过境时刻），此时该输入隐藏 |
| DEM | 可选，m，默认 0 | 太阳位置；EB 中与 ERA5 地形高度（`z`）之差用于订正气温、气压 |
| 经纬度 | 默认由地表类型文件的地理参考换算为 WGS84；也可输入栅格或常数 | 太阳位置与 ERA5 插值 |
| VZA / VAA | 必填，度；VAA 从正北顺时针 | 观测几何，相对方位角 = VAA - 太阳方位角 |

**ERA5 数据。** 菜单“遥感影像模拟 → ERA5 数据”或工作台右上角按钮打开管理面板。一个数据包是一组逐小时 ERA5（0.25°）或 ERA5-Land（0.1°）单层 NetCDF，时间上可以只覆盖一天，也可以覆盖整年（可以按月或按变量分成多个文件）；空间上只需盖住影像范围并外扩约 2 个格点。EB 实际读取过境当天 00 UTC 完整一天（用于首日平均气温初值；数据包不足时取已有小时）到过境后 1 小时（ERA5-Land 另需前一日 23 UTC）；数据包未覆盖必需时段时，工作台与引擎都会给出缺少的变量和时次。整年数据包在 1 月 1 日、12 月 31 日的日界处沿用最近时次。必需变量：`u10 v10 t2m d2m sp ssrd strd skt stl1`；可选：`stl2`、`swvl1`（土壤水分取 ERA5 时必需）、`z`（地形高度订正，可放在单独的不变量文件中；没有 `z` 时即使勾选订正也不会订正，日志会给出警告）。`skt`、`stl1`、`stl2` 仍会在驱动影像中输出，但不再作为土壤初温；土壤初温由首日平均气温决定。“选择 NetCDF 文件并登记”只读取时间轴、检查变量是否逐小时连续，在 `文档\Stream Studio\era5-packs` 下写索引，不复制数据；NetCDF 与索引在同一目录（或其子目录）时索引记相对路径，整个目录可以拷贝给他人使用。工程也可以直接引用工程目录里的数据包（如内置示例“北京市 Landsat 影像-ERA5 单日驱动”），这类数据包标为“工程自带”。文件路径含中文时须能取得 8.3 短文件名，否则请放到英文路径下。登记后文件被修改须重新登记。GRIB 请先转为 NetCDF。

波段：光学内置 Sentinel-2 MSI、Landsat 8/9 OLI、MODIS 1–7、红绿蓝+近红外四种预设，覆盖 400–2400 nm，按高斯响应（半高宽）与参考太阳光谱加权平均；热红外内置 Landsat TIRS、MODIS 31/32、SLSTR S8/S9 和单波段 10.5 μm 预设，按中心波长单色计算（与 TiRT 观测一致，半高宽仅作记录）。预设可以逐行修改，也可以增删波段。

适用范围：结果不含大气，是冠层顶结果。光学与热红外使用 TiRT 标准四组分闭合（`hom3` 节点辐射度、热点、全阶散射）：光学方向反射率 = 一次散射 + 多次散射；热红外 = 四组分有效发射率（含多次散射）与 Planck 辐亮度合成。EB 为单日、均匀冠层的四组分能量平衡，与 TIRTEB 现行公式和默认值一致：短波 0.8/0.2 直散分配并做晴空 DNI 限幅，Raupach 气动阻抗含对流阵风与分段 400 s m⁻¹ 限幅，Farquhar 气孔含 g0 下限，1/L 用区间割线与联合闭合判据，土壤热采用 7 h 表面温度历史（`surface`）或 2 m 土柱（`depth`）。城市像元仍按不透水地面 + 绿地冠层的四组分简化，不与 TIRTEB 的城市多组分逐像元一致。初温、土壤热与成像闭合已改用上述口径，旧版 EB 参考结果会相应变化。需要建筑、树冠等精细三维结构时，应改用 HiStream 三维模式。模型来源与改动见 `models/stream/PORTING.md`。

### 5.3 运行方式：直接模拟与同化（亮温 / 地表温度 / 组分温度）

参数面板最上方的“**运行方式**”只有两个选择：

- **直接模拟**：按“温度来源”（RT 给定组分温度或 EB 能量平衡）正向生成光学与热红外影像；
- **同化**：给定观测数据，选它是什么，直接运行。观测误差、背景误差、迭代方法与收敛条件全部使用内置默认值，界面上不需要设置；发射率不作为同化变量。

同化时“温度来源”面板改名为“**背景场**”：RT 模式下背景是给定的四组分温度，EB 模式下背景是 ERA5 驱动的能量平衡解。

| 同化观测 | 观测文件 | 被更新的量 |
|---|---|---|
| 亮温 | GeoTIFF，波段数等于热红外波段数，依次对应热红外波段表（K，冠层顶、已大气校正）；需启用热红外波段 | RT：Tss/Tsh/Tcs/Tch；EB：土壤水分 + Vcmax |
| 地表温度 | GeoTIFF，1 个波段，按地类固定发射率归一的 LST（K，10.5 μm 约定） | 同上 |
| 组分温度 | GeoTIFF，4 个波段 Tss/Tsh/Tcs/Tch（K） | 同上（RT 下为逐组分直接融合） |

- **光学反射率**（可选）：GeoTIFF，波段数等于光学波段数。给出时同时更新 **LAI**；不给时 LAI 保持输入值。
- **其他视角**（仅亮温）：可添加多个视角，各自一幅亮温文件和天顶角/方位角（常数或栅格），多角度观测提高组分温度的可分离性。
- 观测为 NaN 或超出 150–400 K 的像元视为缺测，不需要另给掩膜；没有观测的像元保留背景值。

操作：选“同化”→选观测类型→选择观测数据（可选光学反射率、其他视角）→点击“**运行同化**”。

**内置可微算子。** 观测算子就是正向成像本身（TiRT 四组分权重 + hom3 多次散射 + 土壤含水量/Hapke 方向发射率 + Planck，光学为 PROSPECT/BSM + hom3 冠层反射），在引擎内以对偶数前向自动微分实现，雅可比是精确导数而不是差分。EB 背景下组分温度由过境时刻能量平衡给出，它对土壤水分与 Vcmax 的导数用收敛点的隐式微分得到（dT/dx = −(∂R/∂T)⁻¹ ∂R/∂x，每像元一次 4×4 求解），土壤水分同时通过土壤发射率、土壤阻抗、热惯量与土壤短波反照率起作用，Vcmax 通过气孔阻抗起作用。

**内置默认值**（写入 `scene_summary.json` 的 `assimilation.defaults`）：观测误差 亮温 0.5 K、LST 1.0 K、组分 2.0 K、反射率 0.02；背景误差 组分温度 5 K（组分间相关 0.5）、土壤水分 0.10 m³/m³、Vcmax 30%（不少于 10）、LAI 30%（不少于 0.5）；MAP Gauss–Newton，RT 最多 20 次、EB 最多 10 次迭代。

| 产品 | 内容 |
|---|---|
| `analysis_components.tif` | 分析场 Tss/Tsh/Tcs/Tch（K）；未同化像元为背景值 |
| `background_components.tif` | 背景场组分温度（K） |
| `analysis_uncertainty.tif` | 分析 1σ：四组分温度、土壤水分、Vcmax、LAI（未作为控制变量的为空） |
| `analysis_qa.tif` | 质量位、热红外 O−B 均值、O−A 均值、O−A RMS（K）、信号自由度 DFS、观测数、迭代次数 |
| `analysis_controls.tif`、`background_controls.tif` | EB 或有光学观测时：土壤水分、Vcmax、LAI 的分析值与背景值 |
| `analysis_fluxes.tif` | EB：分析状态下过境时刻的 Rn、H、LE、G（W m⁻²） |

同化时本次输出的 `optical_reflectance.tif`、`tir_*.tif` 都是分析场的正向图像，可直接与观测比对；EB 的 `components.tif`、`eb_fluxes.tif` 仍是背景解。质量位：0 输入无效/无观测、2 结果越界或控制变量到达边界、3 求解失败、4 病态、8 信息量不足（DFS < 0.2）、9 未收敛；值为 0 表示正常。运行摘要给出同化像元数、平均 O−B、O−A 和平均 DFS。

单独的 LST / LSCT 反演（`lst*.tif`、`lsct*.tif`）仍保留在引擎配置的 `inversion` 块中供脚本调用，工作台不再单独列出；旧工程里的反演设置在打开时转换为对应的同化设置。

**与 LS4T 的分工。** 面向卫星产品的分裂窗 LST、多传感器入口与 L3/L4 产品链由配套的 **LS4T** 工具（`C:\work\ls4t`，Python 脚本）承担；Stream Studio 为它提供输入、验证基准和三维样本，LS4T 的 LST/LSCT 产品也可直接作为本工作台“地表温度”“组分温度”同化的观测。

两类反演产品：

| 产品 | 含义 | 单位 | 典型观测 |
|---|---|---|---|
| LST · 地表温度 | 传感器方向上的像元等效辐射温度，不等于任一组分温度 | K | 两个热红外波段（分裂窗）或单波段 + 外部发射率与大气校正 |
| LSCT · 地表组分温度 | Tss（光照土壤）、Tsh（阴影土壤）、Tls（光照叶片）、Tlh（阴影叶片） | K，4 波段 | 多角度/多波段热红外，加 LAI、结构或光学先验 |

**LST 输入**（LS4T 分裂窗，八特征广义分裂窗）：

| 输入 | 要求 |
|---|---|
| 两波段亮温 | K，必须先做大气校正，否则大气误差全部进入 LST |
| 两波段发射率 | 由 LAI/覆盖度与土壤/叶片发射率混合得到，或外部发射率产品；单波段时必须外部给定 |
| 柱水汽 | 单位与系数表分箱一致（传感器入口为 cm），超出标定域不外推 |
| 观测天顶角 | 度，用于系数在相邻节点间线性插值 |
| 云掩膜 | 云像元标记为无效，不参与统计 |
| 传感器系数表 | 按传感器与大气条件标定；标定域外的场景不应使用 |

**LSCT 输入**：各角度/各波段的观测辐亮度（或可换算的亮温）、观测几何、热红外发射率，以及 LAI 与地类决定的结构权重。求解在辐射域进行，组分温度由逆 Planck 得到。观测数少于组分数时必须借助空间窗口、先验或物理约束，否则问题不可解。

**输出**：LST 为单波段温度图；LSCT 为 4 波段温度图，并附残差、条件数和质量标记。质量标记含义见[理论手册 15.7 节](theory-manual.md#157-产品质量与验证)：`INPUT_INVALID`、`CLOUD`、`OUT_OF_RANGE`、`ILL_CONDITIONED`、`RETRIEVAL_FAILED`。

三种衔接用法：

1. **正向 → 同化（OSSE）**：用本工作台生成的冠层顶亮温，加已知噪声后作为“同化亮温”的观测（或送进 LS4T），与 EB 的 `components.tif` 真值比较，检验同化链与可识别性；真实卫星数据应先做大气校正，卫星产品走 LS4T 的传感器入口。
2. **分析 → 正向**：`analysis_components.tif` 与 `components.tif` 同格式，可作为 RT 模式的组分温度输入；只改波段或观测角时不必重算 EB。
3. **背景场**：EB 的 `components.tif` 或上一景的分析场可作为下一次同化的 RT 背景，用于抑制组分温度的强相关。

**使用注意。**

- **单角度、单波段数据不能独立分离四组分**。单角度亮温只约束组分的加权组合，分析场主要由背景决定（DFS 接近 1）；需要多角度（“其他视角”）或 EB 背景的物理约束。
- 本工作台输出是**冠层顶**结果。同化真实卫星数据前必须先完成大气校正或接入大气产品，否则会把大气误差吸进地表温度。
- 同化给出分析 1σ（由后验协方差传播）；LS4T 产品的不确定度仍由调用者给定（默认 1 K 填满），不是由残差传播得到，不能用它做 68% 覆盖率检验。
- 同化的观测算子与成像使用同一地形处理（面元法坡面几何、山包/山脊复合面元）。单独的 `inversion` 反演仍按水平地表计算权重（日志会提示）。
- EB 同化的导数只对过境时刻求（过境前的土壤热历史视为固定），控制变量变化很大时以多次迭代重新求解能量平衡来修正。
- 窗口反演假设窗口内组分辐亮度常数，在异质地块边界会把两块地混成一个解；边缘像元用不完整窗口，可靠性更低。
- 分裂窗的多次散射因子、发射率来源和 LAI 来源都要随产品记录，同一批产品不能混用不同取值。
- 不收敛、条件数超限的像元必须剔除，不能与正常像元一起统计。

公式、求解器细节和精度目标见[理论手册第 15 章](theory-manual.md#15-地表温度与组分温度反演)；数据契约、算法清单与已知缺口见 [lst-lsct-inversion.md](lst-lsct-inversion.md)。

## 6. 场景设置

### 6.1 坐标约定

用户输入坐标统一为：

- `+X`：北，`-X`：南；
- `+Y`：垂直向上，高度；
- `+Z`：东，`-Z`：西。

方位角 `0°` 指北、`90°` 指东。平行投影输出固定为上北、右东；中心投影的倾斜视场保持天空向上、地平线水平，正下视仍为上北、右东。OBJ、Three.js 与当前计算引擎采用同一空间约定；不要在外部文件与界面之间手工交换坐标轴。

### 6.2 空间范围

“X 尺寸（南北）”“Z 尺寸（东西）”“Y 最大高度”定义计算域和中间场景范围框。它们不是对象的自动缩放系数。

“体元大小”控制 VoxelRT、VoxelEB 及体元化过程。减小体元会增加空间细节，同时快速增加体元数量、内存占用和计算时间。

“OBJ 填充阈值”用于控制三角面与体元相交时的保留阈值。复杂薄片植被可适当降低；噪声面元较多时可适当提高。

可选计算域是一个能够设置 X、Y、Z 尺寸和偏移量的包围盒。Three.js 始终显示完整背景场景和所有对象；勾选计算域后，仅运行时数据被限制到包围盒内：完全在域外的 OBJ/实例直接跳过，跨越边界的对象只保留域内部分，单实例 OBJ 会先按边界裁切三角面，再进行体元化。服务日志会报告原始实例数、保留数、域外跳过数、跨界预裁切对象数和裁切前后面数。移动包围盒不会移动原场景，只是把盒内区域作为新的局部计算场景。

### 6.3 DEM

支持 GeoTIFF 和 ASCII Grid。导入后文件复制到工程 `terrain` 目录，并记录宽、高、像元大小、高程范围和 NoData。

DEM 的水平范围与场景 X（南北）、Z（东西）不一致时，系统将整幅 DEM 双线性拉伸到场景范围。该操作改变水平尺度，不改变原始高程值。若 DEM 高差超过“Y 最大高度”，界面会给出警告，应提高场景高度以避免截断。

内置 DEM 位于 `assets/dem-library`，包括平地、单坡、复合坡、山丘、盆地和起伏地形。

### 6.4 背景属性

背景需要绑定：

- 光谱属性；
- 温度属性；
- 物化属性。

Hapke 角度效应用于面元背景的非朗伯反射和热红外方向发射率。“结构强度”范围为 0–1：0 表示退化为各向同性，1 表示完整应用当前参数化角度效应。当前研究建议主要在 FacetRT/FacetEB 中使用该选项。

## 7. 太阳、天空与传感器

### 7.1 太阳与天空

- 太阳天顶角：0° 为太阳位于天顶，90° 为地平线；
- 太阳方位角：范围 0–360°；
- 直射比例与漫射比例之和固定为 1；
- 天空温度用于热红外下行天空辐射计算。

能量平衡模式会结合气象时间节点更新辐射条件；界面角度仍用于静态模式和初始配置。

“周期穿越次数”范围为 0–20，0 表示关闭。启用后不会复制邻域对象或建立多份场景；射线碰到四个水平边界之一时，把坐标转换到对侧并继续查询。每次穿越消耗一次追踪深度，因此应联合设置追踪深度与周期穿越次数，避免无意义的重复路径。

“天空盒”是独立开关。勾选后使用内置典型天空与云背景作为边界辐射条件；不勾选时使用默认 cosine 天空分布。天空盒只改变边界入射辐射，不复制场景几何。

### 7.2 图像与波段

默认图像分辨率为 512 × 512。输出分辨率与 FacetRT 内部可见性栅格相互独立。

“自定义波段”使用 nm，多个波段可用空格、逗号或分号分隔。例如：

```text
450 550 670 720 800 10500
```

打开“连续波段模拟”后填写起始、结束和间隔。连续波段与自定义波段合并、去重并升序排列，最多 800 个波段。

### 7.3 投影与观测角

平行投影用于卫星、航空和方向性研究：

- 单角度：填写观测天顶角 VZA 和观测方位角 VAA；
- 主平面批量：-75° 到 75°，间隔 5°，包含太阳主平面及其垂直平面；
- 半球观测：128 个近似等面积方向。

角度效应极坐标图按 0–360° 周期补全方位角，用首尾相接方式避免 0°/360° 接缝；主平面横轴仍按 -75° 到 75° 显示，不扩展到 ±90°。

中心投影用于透视相机，需要填写传感器北向 X、东向 Z 和高度 Y。传感器位置应在场景上方，且视场应覆盖研究区。视场天顶角 `0°` 为正下视，角度增大后逐渐转为前视；启用巡航时，相对飞机方位角 `0°` 为前方。倾斜影像采用相机竖直向上基准，避免地平线因地图上北约束而旋转成侧视。

## 8. 场景对象

### 8.1 OBJ 实体

点击“导入 OBJ 实体”，选择带有效三角面的 OBJ。MTL 仅用于可视化参考，不参与 HiStream 计算；计算属性必须在导入对话框中绑定。

推荐在建模软件中完成：

- 删除退化面和重复顶点；
- 应用缩放和旋转；
- 保证单位与工程的米制单位一致；
- 统一正面方向；
- 按需要保留 Mesh 名称，以便分别绑定属性。

内置 OBJ 位于 `assets/obj-library`，已按建筑、植被、作物、车辆、船舶、飞机、特种车辆、地形和大型场景分类。作物目录提供玉米、小麦、水稻和向日葵单株低模；植被目录提供阔叶树、橡树、松树、棕榈、杨树和柏树等模型。

### 8.2 PRIM 原型

PRIM 可生成立方体、椭球、混沌介质和水面。它适合规则对象、参数实验和不需要外部网格的场景。

水体可选择矩形或圆形/椭圆水面，并设置位置、尺度和偏移。水面默认略高于背景，以避免与土壤面完全重合。崎岖水边界应使用外部 OBJ 或 DEM 与局部水面组合表达。

### 8.3 火焰

火焰是参与介质，不是普通发光表面。默认尺寸为长 25 m、宽 25 m、高 10 m，位置仍按 X 北向、Z 东向、Y 高度填写。

当前限制：

- 火焰辐射只接入 VoxelRT/VoxelEB；
- VoxelEB 可计算烟雾浓度输送；
- 烟雾浓度尚未反馈到最终辐射图像；
- “新增雾”用于建立有限范围的局部雾体积，可设置消光系数、单次散射反照率、散射非对称因子和温度；
- 大尺度均匀雾霾仍建议通过“大气影响”中的 MODTRAN 参数处理，局部雾与 MODTRAN 大气可以分别启用。

### 8.4 实例分布

支持随机分布、规则网格、单实例和自定义坐标。OBJ 实体与 PRIM 原型共用同一位置文件格式；单个对象最多支持 100000 个实例。

随机和规则分布可按数量或面密度控制。X/Z 最小值和最大值按用户填写的范围采样，不根据 OBJ 外包围盒自动收缩；对象局部超出场景范围是允许的，但超出计算域的部分不会产生有效结果。

整体偏移 X/Z/Y 在生成坐标后统一叠加，适合修正坐标基准偏差。

自定义 TXT 每行格式：

```text
X_north Z_east Y_height scale rotation
```

支持空格、Tab 或逗号分隔。至少提供北向 X 和东向 Z；高度 Y 缺省为界面当前高度，缩放缺省为 1，旋转角缺省为 0。

Three.js 为保证交互性能，对大量实例最多抽样预览 5000 个；预览数量不代表计算数量，完整实例仍写入工程位置文件并参与正式计算。

### 8.5 随机移动

人、车辆和船舶可启用随机移动，设置平均速度、速度扰动、活动半径、转向间隔和随机种子。该功能当前用于 Three.js 动态场景预览，并保存到 `project.json`；它不是交通流或人群动力学求解器。

## 9. 材质属性

### 9.1 四类属性

每个对象分别绑定：

1. 光谱特征：反射率、透射率及热红外参数；
2. 温度特征：阳面和阴面初始温度；
3. 结构参数：混沌介质、刚体、火焰或雾；
4. 物化属性：植被生化、土壤热物理或水体参数。

OBJ 可按 Mesh 分别绑定光谱和温度。建筑、车辆、船舶等不透明对象通常绑定“刚体”结构；植被绑定“混沌介质”。

太阳能板与其他地物统一通过“导入 OBJ 实体”选择，四种板形 OBJ 位于 `assets/obj-library/solar/`。OBJ 只定义三维形状：树形 OBJ 可保留植被标识并绑定光伏物化属性、不透明光谱和刚体结构，使用 FacetEB 输出温度、发电功率、累计电量及热平衡过程；板形 OBJ 也可设为植被并绑定植被光谱、生理生化及结构参数，运行对应植被过程。修改对象物化属性会同步到全部 Mesh，之后仍可按 Mesh 分别设置。物化属性的手动选择不再被树干、树枝或树叶的 Mesh 名称覆盖。代表性光谱用于快速建模，定量研究应替换为具体组件的实测光谱与厂家效率参数。

### 9.2 光谱来源

支持：

- 自定义面板数值；
- PROSPECT 叶片模型；
- BSM 土壤模型；
- 波谱 TXT 文件。

界面内置玉米、小麦、水稻、衰老作物、阔叶树和针叶树的 PROSPECT 参数预设，以及干湿壤土 BSM 预设。`assets/spectral-library` 还提供作物、树木、土壤、沥青、混凝土和水体的可导入 TXT 示例；这些示例用于快速测试，正式定量研究应优先使用实测光谱。

“Three.js 预览纹理”是独立的外观设置，可选择红砖墙、石子路、混凝土墙、粉刷墙、自然石墙、红瓦、金属、木材、草地、帆布、林地迷彩、荒漠迷彩、数码迷彩、遮阳条纹和遮阳网，并设置纹理重复尺寸。预览纹理仅用于编辑器显示，不参与 HiStream 求解，也不改变反射率、发射率或最终模拟结果；“物理纹理”仍是另一项可选的短波反射率空间方差参数，可选内置模板，也可通过“导入纹理图像”使用自己的 PNG/JPG/TIF（复制到工程 `textures/` 目录）。

波谱 TXT 必须为 2 行或 3 行：

```text
wavelength_1 wavelength_2 ...
reflectance_1 reflectance_2 ...
transmittance_1 transmittance_2 ...
```

第三行可省略，此时透射率为 0。波长、反射率和透射率数量必须一致，且反射率与透射率之和不能超过 1。

### 9.3 水体

水体光学使用 Fresnel–Cox–Munk 参数化，主要参数包括折射率、坡度方差和漫反射比例。坡度方差为 0 时，辐射传输使用稳定的中等风速默认水面。Three.js 波浪只是可视化效果，物理辐射由水体材质参数控制。

水温由能量平衡、体积热容量、混合层深度和蒸发系数共同控制。仅设置初始水温不会使水温保持恒定。

### 9.4 篷布、遮阴棚与遮阳网

篷布、遮阴棚和遮阳网都按“薄膜”建模。光谱图像可用 RayTracing 或 FacetRT，温度需用 FacetEB；三者都支持透射率、开孔率和物理纹理。体元模式把刚体当作不透光实体，这三项都不生效；VoxelEB 拒绝薄膜物化属性。示例工程可用 `node tools/generate-tarp-example.mjs <输出目录>` 生成（自包含，复制 OBJ 和所需 `assets/` 文件）。

示例中两种篷布各有四套方案（光谱名带“方案 A/B/C/D”，D 为分类纹理/开孔率纹理），在“场景对象 → 属性”的 Mesh 表中把 `part_1__covered_car`（车罩）或 `canopy_fabric`（遮阴棚）的光谱切换为对应方案即可；纹理随光谱一起切换。新建方案可在“材质属性 → 光谱特征”中复制现有方案后改光谱文件和纹理模板。

| 设置 | 位置 | 说明 |
|---|---|---|
| 光谱 | 光谱特征 → 导入波谱 TXT | 反射率和透射率按波长给出；两面共用同一组光学参数，透射按漫射处理。`assets/spectral-library/tarp_*.txt` 提供军绿帆布、荒漠沙色、白色 PE、镀铝反光膜和仿植被伪装布的代表性光谱 |
| 热红外 | TIR 反射率 / TIR 透射率 | 发射率 = 1 - TIR 反射率 - TIR 透射率。镀铝膜约 0.28，帆布约 0.90 |
| 纹理 | 物理纹理 | 按图像亮度调制短波反射率（各波段同一倍率，面积平均不变）；不改变透射率和热红外。“反射率变异系数 CV”直接指定反射率的相对标准差（如 0.10 表示 ±10%），图像只决定斑块形状和尺度；CV 为 0 时按“方差强度”缩放（实际 CV 约为强度的 1/4）。背景地面也可使用：在背景光谱上启用物理纹理即可，无 DEM 时 RayTracing 会把平地面按体元大小细分成网格。每个三角面只取面心一个值，篷布网格应细于迷彩斑块。RayTracing 与 FacetRT 的倍率完全一致。内置模板：混凝土、砖墙、沥青、金属、帆布织纹、林地/荒漠/数码迷彩、遮阳条纹、褶皱反光膜、沙面风纹、裸土斑块。需要不同斑块使用不同光谱时，使用下方“光谱分类纹理” |
| 开孔率 | 光谱特征 → 开孔率 | 遮阳网、穿孔篷布使用。光谱中填纤维本身的值，运行时换算为 R′=(1-O)R、T′=O+(1-O)T，热红外同理。孔中直射光按漫射透过，棚下不形成光斑。仅自定义和 TXT 光谱可用 |
| 光谱分类纹理 | 光谱特征 → 光谱分类纹理 | 一张无损 PNG，每种颜色绑定一条光谱（界面自动读出图中占比 ≥ 0.5% 的颜色）。运行时每个三角面按面心取色，归入颜色最接近的类别并改用该类别光谱，包括其透射率、热红外、物理纹理和开孔率。用于多光谱迷彩：例如浅绿斑用仿植被光谱、褐斑用土壤光谱。内置林地 4 类、数码 4 类、荒漠 3 类 |
| 开孔率纹理 | 光谱特征 → 开孔率纹理 | 一张灰度 PNG，亮度在最小、最大开孔率之间线性映射（黑 = 最小，白 = 最大），量化为 2–32 档；每档派生一条开孔率光谱。用于遮阳网破损、织物疏密不均。内置“遮阳网破损”“织物疏密不均” |
| 热物性 | 物化属性 → 篷布/织物薄膜（FacetEB） | 单层薄板，两面同时辐射和对流，不计蒸腾。面热容 = 面密度 × 比热容：PVC 帆布约 800，PE 篷布约 300，HDPE 遮阳网约 100–300 J·m⁻²·K⁻¹；开孔网可再乘以 (1-O)。不要用“建筑表面”代替：FacetEB 中物体面元默认面热容为 60000，相当于厚板 |

光谱分类纹理和开孔率纹理在运行准备阶段处理：把每个三角面按取值重新分组，分组绑定对应光谱，所以对所有计算模式生效（体元模式按体元平均）。纹理按对象自身坐标、面法线的主轴方向投影，图案随对象移动；每个三角面只取一个值，网格需细于斑块（破损孔洞应大于网格）。运行日志会列出各类别或各档位所占的面数比例。

篷布直接覆盖在车上时，可用 `assets/obj-library/vehicle/realistic/covered_car_realistic.obj`：`part_1__covered_car` 为车罩，`part_2__covered_car` 为车轮；车身本体未建模。遮阴棚可用示例中的 `models/shade_canopy.obj`（`canopy_fabric` 篷布、`canopy_frame` 支架），篷布网格为 0.1 m。

## 10. 气象驱动

气象驱动主要用于 FacetEB 和 VoxelEB。默认观测高度为 15 m。

设置项包括开始节点、结束节点、时间步长、年份、时区、经纬度、观测高度、初始土壤温度和饱和含水量。界面默认显示开始节点 1、结束节点 48；后端按左闭右开区间 `[start, end)` 处理，即包含开始节点、不包含结束节点，默认实际计算节点为 1–47。

气象文件中的时间为当地时间的年积日。太阳位置按“年份”（默认 2019，决定闰年与 ΔT）和“时区”（默认 UTC+8，单位小时，可为小数，如印度为 5.5）解释这些时间；站点不在东八区时需修改时区，否则太阳方位与高度会错位。工程文件中对应 `configuration.meteo.year` 与 `configuration.meteo.timezone`，旧工程缺省时沿用上述默认值。

气象文件第一行为记录数，之后每行 7 列：

```text
JulianTime  Ta  ea  p  u  Rin  Rli
```

| 列 | 含义 | 常用单位 |
|---|---|---|
| JulianTime | 年积日及日内小数 | day |
| Ta | 空气温度 | °C |
| ea | 水汽压 | hPa |
| p | 气压 | hPa |
| u | 观测高度风速 | m/s |
| Rin | 下行短波辐射 | W/m² |
| Rli | 下行长波辐射 | W/m² |

导入文件后系统复制到工程 `meteorology` 目录。开始、结束节点必须位于文件记录范围内。

## 11. 大气影响

“大气影响”与“气象驱动”相互独立。前者处理地表到传感器之间的辐射传输，后者驱动地表能量平衡。

当前界面只保留关键参数：

- 大气类型：热带、中纬度夏季、中纬度冬季；
- 柱状水汽量 PWV：0.5–5 cm；
- 气溶胶类型：乡村型、城市型；
- 能见度：10–50 km。

能见度作为 MODTRAN 气溶胶负荷输入，不再同时填写 AOD。传感器高度和观测角从工程自动读取。LUT 覆盖 350–14000 nm，并在水汽、能见度、高度、观测角和波长之间插值。

短波输出是无量纲方向反射因子，当前大气处理仅乘地表到传感器路径的透过率。相对光照模型未提供绝对光谱入射辐照度，因此不叠加有单位的程辐射，也不表示完整的短波大气散射模拟。热红外在辐亮度域应用透过率和程辐射，温度输出随后进行逆普朗克换算。

背景表面的镜面开关位于“场景 → 背景属性 → 背景使用镜面反射”，仅控制背景；镜面比例和粗糙度仍读取背景绑定的光谱属性。旧工程的有效背景镜面状态会迁移到该开关。

启用大气后，输出文件增加 `_a.tif` 后缀；不启用时不增加该后缀。

## 12. 流体力学

DEM 面板现提供 VoxelEB 的“地形水热经验场”：气温递减率、水汽压尺度高度和土壤含水量指数场可独立配置，详见 [HiStream 地形水热经验场](histream-terrain-environment.md)。旧工程默认关闭；这些是需当地标定的经验输入场，尚不包含完整水量收支。

流体模块默认关闭，当前只接入 VoxelEB。未选择 VoxelEB 时，左侧显示“仅 VoxelEB”。

### 12.1 网格与显存

流体体元默认等于场景体元，但可以单独修改。空气网格显示为：

```text
X × 高 × Y
```

界面按每个流体单元约 236 字节估算状态显存，其中包含 D3Q19 双缓冲分布函数、宏观速度、温度、烟雾、密度和介质标记。实际显存还包括辐射、体元、加速结构、图像和驱动开销，因此不能把该估算当作整次模拟的显存上限。

### 12.2 边界和参数

- 来流风速逐时间读取气象文件；
- 来流风向 0° 沿场景正 Y，90° 沿正 X；
- 数值限速上限只防止数值发散，不是入射风速；
- 建筑和刚体是固体边界；
- 混沌介质是多孔阻力区；
- 火焰可提供温度和烟雾源。

流体采用 D3Q19 BGK 格子玻尔兹曼方法。物理风速使用整次模拟固定的比例映射到格子速度，气象来流不超过 0.08，避免不同气象节点切换时重新解释已有分布函数。界面时间步是温度和烟雾输运的上限；每个气象节点还会至少执行一次来流穿越计算域所需的 LBM 迭代。流体体元过细会显著增加格子数量和迭代次数，应优先根据场景尺度选择合理体元大小。

LBM 得到的局地风速参与空气动力阻力计算，局地空气温度参与显热、潜热和表面温度迭代；因此建筑绕流和树冠减速会反馈到 VoxelEB 能量平衡。耦合按气象节点显式交错推进。

### 12.3 输出

风速和气温默认不输出。勾选后按气象时间节点写入 `output`：

- `fluid_wind_H=..._T=....tif`：水平风速大小、X 分量、垂直分量、Y 分量；
- `fluid_air_temperature_H=..._T=....tif`：空气温度，单位 °C。

默认请求高度为 2 m。实际输出对应最近的流体体元中心，界面会显示解析后的真实高度。建筑内部为 NoData，不应解释为有效空气温度或风速。

风矢量图采用自适应抽样，箭头方向来自分量，颜色来自风速大小；色标默认按有效像元的 2%–98% 分位拉伸。

## 13. 仿真控制

### 13.1 输出项

- 图像：输出 GeoTIFF；能量平衡模式为逐时间节点输出；
- 辐射过程：保存短波、长波、净辐射或辐射度过程；
- 能量过程：保存潜热、显热和表面热通量；
- 碳同化：VoxelEB 开启能量过程后同时保存 `gpp` 和 `npp`；
- 温度：热红外图像以亮温形式输出；
- 反照率：按当前模式输出反照率结果。

过程输出会显著增加文件大小，只在需要三维诊断时开启。“统计”始终输出。`gpp` 为叶片总光合，`npp` 为当前叶片净同化近似，单位均为 `μmol CO₂ m⁻²叶面积 s⁻¹`；非植被体元为 0。夜间 GPP 应接近 0，NPP 可能因暗呼吸而为负。

### 13.2 计算参数

- 追踪深度：控制多次散射或路径深度；
- 周期穿越次数：0–20；边界穿越一次等价于消耗一次路径深度，不在原路径基础上叠加整套邻域查询；
- 采样数目：控制随机/方向采样精度；
- 计算设备（左侧“计算模型”下方）：列出引擎检测到的 GPU（`histream --list-devices`），以及 CPU 和“自动”。GPU 编号即工程中的 `control.gpu`；不满足当前模式要求的 GPU 显示为不可选。FacetRT/FacetEB 的 CPU 版为原生 OpenMP 多线程软件栅格可见性、Jacobi 辐射度迭代与能量平衡；VoxelRT/VoxelEB/Raytracing 的 CPU 版通过随引擎发布的 Mesa lavapipe 软件 Vulkan 驱动（`engine/lavapipe/`）多线程运行同一套着色器与光线追踪。自动模式在 GPU 不可用时回退到 CPU。CPU 版明显慢于 GPU，建议先降低采样数和分辨率试算；也可用环境变量 `HISTREAM_COMPUTE_BACKEND=cpu|gpu|auto` 覆盖体元/光线追踪模式的设置；
- CPU 线程（选择 CPU 或自动时显示）：`control.cpuThreads`，默认 32，本机逻辑处理器少于 32 时按本机数量；可调范围 1 至本机逻辑处理器数。FacetRT/FacetEB 按设定值运行；VoxelRT/VoxelEB/Raytracing 受随附 Mesa lavapipe 的内置上限（当前 32 线程）限制，超出部分界面会提示；
- 异质性体元：仅 VoxelRT/VoxelEB；默认关闭；
- 辐射求解方法：传统稳健方法或加速方法。

VoxelRT 的加速模式每批最多同时求解 4 个相邻波段，共享几何遍历，不进行波段插值。FacetRT 的加速模式复用相邻同类型波段的初始辐射度并按残差提前收敛。

### 13.3 能量平衡参数

土壤温度方法：

- 0：瞬时能量平衡；
- 1：热惯性动态模型；
- 2：温度廓线传导模型（默认）。

FacetEB 的方法 2 使用 12 层有限体积隐式传导，层边界为 0、0.01、0.025、0.05、0.1、0.2、0.35、0.55、0.8、1.1、1.5、2、3 m。各层初温取工程初始土壤温度，3 m 下边界保持该温度；层温随气象节点连续推进。表面热通量包含向下传导，满足“表面通量 = 底部通量 + 柱储热”。该配置暂不包含水分迁移、冻结融化或分层热物性。方法 0 仍为 `G = 0.35 Rn`，方法 1 仍为热惯性历史卷积。

植被温度方法：

- 0：Ball–Berry 经验耦合；
- 1：Farquhar 机制耦合。

面元机制法使用 C3 Farquhar / C4 von Caemmerer 光合方程，将光合速率经气孔阻力耦合到潜热和叶温。修改目标叶片所绑定物化属性中的 `Vcmax` 后重新运行即可产生响应；还会读取 `m`、`BallBerry`、`Type`、`kV`、`Rdparam`、`stressfactor`、`Tyear`、`beta`、`qLs` 和 `kNPQs`。`Vcmax` 以 25 °C 为基准，单位为 µmol CO₂ m⁻² s⁻¹。机制法始终使用其自身温度响应；`Tcor` 和 `Tparam` 只控制方法 0 的温度修正。夜间、弱光或强胁迫时，Vcmax 对温度的影响可能很小；木质及其他非叶片材料不执行叶片光合计算。SCOPE 对比资料位于项目外的 D:\cases\StreamStudio\模型对比\SCOPE，仅在用户明确要求时使用。

土壤热红外发射率随含水量变化：对 BSM 光谱材质，热红外反射率在“TIR 反射率”（干端，`SMC ≤ 0.05 m³/m³`）与“湿端 TIR 反射率”之间按含水量插值，权重与 BSM 反射率共用同一几何 `1 - exp(-(SMC - 0.05)/0.25)`，`SMC` 即光谱材料中的土壤含水量。湿端留空时取干端发射率 +0.03（上限 0.995）；含水量只降低热红外反射率，因此发射率随含水量单调不减。发射率仍按 1 - TIR 反射率 - TIR 透射率 计算，FacetEB/VoxelEB 的发射、长波交换与成像亮温同步变化；叶片、混凝土和导入波谱等非 BSM 材质不受含水量影响。物化属性里的“土壤含水量 SMC”是水热参数（蒸发干湿判据），不改变发射率。

RT–EB 耦合参数包括光谱加速宽度、最大耦合迭代、温度收敛阈值和温度松弛系数。默认光谱加速宽度为 100 nm。

FacetEB 新建项目默认最多 60 次耦合迭代，已有项目显式保存的迭代上限保持有效。每次辐射耦合迭代均联合求解叶温、叶表湿度与气孔阻力，取消后半程冻结气孔。固定阻力的温度内层使用区间保护 Newton 求解，再在阻力外层闭合生理方程，避免极干条件下固定叶温的湿度解发生分支跳变。收敛同时检查温度变化、能量残差、气孔方程和稳定度变化；叶片能量残差还须不超过 1 W/m²、气孔阻力对数失配不超过 0.001，达到迭代上限不等于收敛。

FacetEB 可在“大气稳定度”中开启 Monin–Obukhov 稳定度修正；兼容默认值为中性大气。稳定度修正会显著改变夜间交换，不能直接沿用中性配置的验证误差。每个地面柱由显热通量更新 Obukhov 长度及冠层/土壤阻力；使用稳定和不稳定相似函数，适用区间限制为 -5 ≤ (z-d)/L ≤ 1。这是柱尺度交换参数化，不是三维流场计算；建筑/光伏物体的强迫对流经验系数保留。`diagnostics/facet_physics_node=*.json` 保存稳定度收敛信息；开启能量过程输出后还保存各柱阻力和方法 2 的土壤温度剖面。

FacetEB 的短波净辐射按窗口分别积分直射和漫射，再累加各窗口；最终传感器图像仍对选定波段逐个求解。VoxelEB 的直射和漫射都服从相同的窗口加速。

## 14. 运行与结果

点击“运行模拟”后，中部进度区以 10 个矩形块、百分比、当前阶段和耗时显示状态。只有日志出现“模拟完成”且退出码为 0，才表示运行成功。

FacetRT/FacetEB 启动前会按 OBJ 三角面数 × 实例数预估展开面元规模。超过 100 万个三角面时不启动面元引擎，并推荐切换到对应的 VoxelRT 或 Voxel RT–EB 模式。

VoxelRT/Voxel RT–EB 会先用 OBJ 三角面进行体元化，再为每个有效体元生成三个正交中面（共 6 个代理三角形）供 GPU 射线相交；不会生成完整六面立方体，也不会把这些代理三角形送入面元模式求解。辐射、温度和能量数据始终按体元保存。

FacetEB 结果后处理按单个时间节点工作：当前节点的 TIFF、辐射过程和能量过程完成后即释放内存，最后一个观测角结束后删除该节点临时 `.bin`，不会把首节点或所有节点数组保留到最后。该策略降低时间序列的峰值内存，但单节点影像或场景本身过大时仍可能超出内存。

典型输出命名：

```text
SZA=..._SAA=..._VZA=..._VAA=..._f.tif
SZA=..._SAA=..._VZA=..._VAA=..._v.tif
T=DOY..._VZA=..._VAA=..._f.tif
T=DOY..._VZA=..._VAA=..._v.tif
```

其中 `_f` 表示面元，`_v` 表示体元，`_a` 表示经过大气传输处理。

结果类型：

- GeoTIFF：图像或高度切片；
- `result_statistics_*.csv`：每个波段的数量、最小值、最大值、均值和标准差；
- `process/*.json` 与二进制数据：三维过程结果；
- Facet 结果 JSON：面元几何、可见性和求解量。

图像显示采用有效像元的 2%–98% 分位拉伸并显示 colorbar。该拉伸只改变显示，不改变 GeoTIFF 原始数值。

三维分析为保证交互速度可能抽样显示体元。触发抽样时界面明确标注“当前为抽样显示，结果文件已保存全部体元。”抽样只影响 Three.js 显示，不影响计算和磁盘结果；流体三维结果统一命名为“体元流体力学”。空气温度图与风速图使用相同的显示区域尺度。

VoxelEB 选择“2 · 温度廓线传导模型”并开启能量过程输出后，“三维分析”会增加“多层土壤温度”。模型输出 0、0.02、0.04、0.10、0.20、0.40、0.60 和 1.00 m 共 8 个真实计算层；每个土壤体元只维护一条实际土柱廓线，表层温度由当前阳照比例合成，阳影温差随深度传导衰减，1.00 m 层固定为该土壤材料的 `Tsoil`。界面将各层等距展开以便观察，并使用统一温度色标。可逐层显示或隐藏，非土壤体元作为 NoData 不参与绘制。

“分析 → 变化分析”可选择两幅同尺寸图像，显示差异图和散点图。比较前应确认波段、单位、投影方向、空间范围和大气标识一致。

## 15. 推荐工作流程

1. 新建工程并设置场景范围；
2. 导入 DEM，检查高差与最大高度；
3. 导入 OBJ 或创建 PRIM；
4. 设置分布，检查 Three.js 外轮廓和坐标；
5. 为背景及每类对象绑定光谱、温度、结构和物化属性；
6. 设置太阳、传感器、波段和观测角；
7. 能量平衡任务导入气象文件并检查节点；
8. 按需启用大气或 VoxelEB 流体；
9. 首先使用小分辨率、少波段、少时间节点试运行；
10. 检查结果方向、范围、NoData 和数量后再运行正式任务；
11. 保存工程及参数版本，记录软件提交版本和显卡环境。

## 16. 常见问题

### 16.1 `OBJ has no faces` 或 `OBJ has no triangles`

OBJ 中没有可用三角面，或文件只是引用外部几何。应在建模软件中三角化并重新导出，而不是使用仅含实例位置的占位 OBJ。

### 16.2 `Direct-light A-buffer overflow`

单个可见性栅格像元内的片元层数超过上限，常见于高密度植被、重叠建筑或大量共面三角形。当前 FacetRT 会根据场景自动在 16、32、64 层间调整；仍溢出时应清理重叠面、提高内部可见性栅格有效分辨率或改用体元模式。

### 16.3 图像方向翻转

不要在 OBJ、位置 TXT 和界面之间手工交换坐标轴。系统会统一面元、体元和 RayTracing 的输出方向。若只有某个外部 OBJ 异常，应检查该 OBJ 的坐标系和面法向。

### 16.4 场景范围框明显过大

范围框严格读取场景 X（南北）、Z（东西）和 Y 最大高度。检查是否把 500 m 误写为 5000 m，或把对象高度写入场景水平尺寸。背景底座不会自动扩大计算域。

### 16.5 风场向中心汇聚

确认使用当前引擎。当前边界为上游定值入口、下游开放出口、侧边自由滑移，不是四周刚性壁。还应检查来流风向和气象风速是否合理。

### 16.6 2 m 气温在建筑内有值

当前版本把固体单元写为 NoData。若仍显示数值，通常是旧结果、显示器未识别 NoData，或请求高度对应的实际体元中心不在 2 m。重新运行并查看文件元数据。

### 16.7 风速颜色集中在低值

“数值限速上限”不是色标最大值。界面根据有效风速的 2%–98% 分位拉伸；少量高速异常不会压缩主要颜色范围。

### 16.8 模拟运行很慢

依次检查图像分辨率、波段数、观测角数、时间节点、对象三角形数、体元大小、过程输出和采样数。Facet 模式保留表面细节，通常比 Voxel 模式慢；高光谱任务应使用加速模式和合理光谱窗口。

### 16.9 `Array buffer allocation failed`

该错误表示结果转换阶段无法分配所需的连续数组。常见原因是“影像分辨率 × 波段数 × 观测角数 × 时间节点”组合过大，或同时保存了大量面元/体元辐射与能量过程；复杂场景和过多可见面元也会间接放大结果。

按以下顺序缩减任务后重试：降低影像分辨率、减少波段、减少观测角、缩小时间节点区间、关闭暂时不需要的辐射/能量过程输出；面元复杂场景改用 VoxelRT 或 Voxel RT–EB。当前 FacetEB 已按节点释放后处理内存，因此仍报错时应重点检查单节点输出规模和场景规模。

### 16.10a FacetEB 逐节点输出与内存

网页服务启动新版 FacetEB 时，每个气象节点计算完成后先保存节点数据，释放求解临时数组，再由独立出图线程依次生成该节点各观测方向的 TIFF。全部方向成功后删除该节点的临时 `.facet_steps/energy_T=*.bin`，销毁出图线程，随后继续下一节点；正式 TIFF、CSV 和已选过程数据不删除。未开启图像时同样逐节点完成保存和临时文件释放。

跨节点保留的是上一节点温度、累计发电量，以及共享的几何、材质和可见性图；不会保留上一节点整套光谱和能量输出数组。TIFF 采用分块写入，避免额外复制整幅图像。出图失败时停止后续计算并保留失败节点的二进制文件，便于排查。直接运行命令行引擎仍保留原有批量输出流程。

该机制降低时间序列输出的内存峰值，但不会消除单节点的多波段数组、GPU 可见性图或几何本身的开销；超大面元场景仍建议使用体元模式。

### 16.10 面元规模超过安全上限

FacetRT/FacetEB 的安全上限为 `MAX_FACET_TRIANGLES = 1,000,000`。预估值按 OBJ 多边形三角化数乘以实例数累计，超过上限会在启动引擎前直接阻止处理。这不是安装包中 15 MiB OBJ 筛选规则；前者约束运行期展开面元数量，后者只控制随安装包分发的单个 OBJ 文件大小。请分别切换 FacetRT → VoxelRT，或 FacetEB → Voxel RT–EB。

### 16.11 `VK_ERROR_DEVICE_LOST`

该错误表示 GPU 驱动终止了当前 Vulkan 任务，常见原因包括体元过细、采样/深度过高、观测方向过多、过程输出过大或旧进程仍占用显存。先点击“重置”结束相关进程，再增大体元、降低采样与追踪深度、减少观测方向并分批运行。周期穿越不会复制四份邻域几何，但每次穿越会增加后续路径查询，仍应限制穿越次数。

## 17. 数据与结果质量检查

从 1.1.1 起，每轮网页或桌面模拟使用 `配置输出目录/runs/<runId>`。结果面板显示本轮实际目录；`run-manifest.json` 保存请求节点、实际产物、输入和引擎哈希及最终状态，`input/` 保存本轮运行配置和气象快照。旧结果不删除。

FacetEB 显示“未收敛”时结果仍会保留，但该节点未满足配置的温度容差和能量残差对应温差容差。先检查材质、驱动与残差，再调整迭代预算；不要把退出码 2 或 `converged=false` 当成成功收敛。

正式使用前至少检查：

- 场景单位为米，坐标和高度方向一致；
- OBJ 法向、三角化和实例数量正确；
- 光谱范围覆盖全部传感器波段；
- 反射率、透射率和发射率满足能量约束；
- 气象温度、气压、风速和辐射单位正确；
- 模拟与观测具有相同空间分辨率、波段响应、观测角和时间；
- 大气前后结果使用 `_a` 标识区分；
- 变化分析只比较相同物理量和单位；
- 植被 GPP 白天应随有效光照增强、夜间接近 0；NPP 可因暗呼吸为负，当前数值是叶片尺度近似，不能直接当作扣除根、茎等全部自养呼吸后的生态系统 NPP；
- 关键实验同时保存 `project.json`、统计 CSV 和运行日志。
