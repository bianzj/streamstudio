# STREAM 模拟示例：MODIS 1 km + Landsat 30 m

状态：示例设计（2026-10-27，第二版），未改代码。替换第一版的“300 m 单时刻 + 30 m 连续时间”。

规则不变：

- **时间**：单一时刻，或连续时间（起、止、步长）；
- **热红外组分温度**：只有两种来源，**ERA5 能量平衡**或**组分温度文件**（已算好的）；不再手工输入；
- 其余输入（地类、LAI、DEM、土壤水分、观测角、波段）两种来源共用。

## 0. 为什么是这两个

两类用户的数据、时间、角度习惯正好相反，能把表单的两个分叉（时间方式、温度来源）都用到：

| | MODIS 级 1 km | Landsat 级 30 m |
| --- | --- | --- |
| 典型用途 | 区域热环境、LST 日变化、与 MOD11/MYD11 产品对比 | 城市/田块尺度的热异质性、与 Landsat B10 对比、新载荷论证 |
| 重访 | Terra/Aqua 每天 4 次（昼 2、夜 2） | 16 天 1 次，上午约 10:30 |
| 时间方式 | **连续时间**（看日变化，从中取过境时刻） | **单一时刻**（就是那一景） |
| 观测角 | 扫描 ±55°，地表 VZA 可到 65°，**逐像元栅格** | ±7.5°，**常数 0°** 即可 |
| 波段 | MODIS 1–7 + 31/32 | OLI B1–B7 + TIRS B10/B11 |
| 一个 ERA5 格点（0.25°）覆盖 | 约 25 × 28 像元：驱动在景内有空间变化 | 约 830 × 930 像元：整景驱动近乎均匀，异质性全部来自地类、LAI、DEM |
| 地表输入来源 | MCD12Q1（IGBP）、MCD15A2H（LAI）、GMTED/SRTM 聚合 | WorldCover/FROM-GLC 重分类为 IGBP、Landsat 地表反射率估 LAI、SRTM 30 m |

## 示例 A：MODIS 级 · 京津冀北部 1 km · 连续时间

范围 114.5–118.5°E、38.5–42.0°N（约 340 km × 390 km，0.01° 网格约 400 × 350 像元）。这个范围和时段正好落在现有 ERA5 包（`landsat_beijing_eb/era5`：38–42.5°N、114–119°E，2019-08-15 00–23 UTC）内，外扩 2 个格点，不用重新下载 ERA5。

### A1　ERA5 能量平衡，一天连续

| 项 | 填写 |
| --- | --- |
| 地表 | 1 km 的 type（MCD12Q1 IGBP）、LAI（MCD15A2H，8 天合成）、DEM；土壤水分留空，取 ERA5 swvl1 |
| 时间 | **连续时间** 2019-08-15 00:00 → 22:00 UTC，步长 **30 min**，共 45 个时刻（北京 08:00 → 次日 06:00） |
| 观测几何 | VZA 0°、VAA 0°（先看天底的日变化） |
| 光学 | MODIS 1–7（太阳在地平线下的时刻跳过） |
| 热红外 | MODIS 31/32；组分温度 **ERA5 能量平衡**，数据包同上 |

步长取 30 min，是为了让 Terra、Aqua 的四次过境（约 02:30、05:30、14:30、17:30 UTC）都落在序列上。能量平衡从 00 UTC 一次推进到 22:00，ERA5 逐时，请求时刻作为额外时次插进去（引擎现在已经这样处理单个过境时刻）。

输出：

```
output/jjj_modis_1km_<时间戳>/
  series.json                 时刻 → 子目录
  components.json             时刻 → 各时刻 components.tif（供复用）
  20190815T0000Z/ … 20190815T2200Z/   每个时刻一套产品，产品名同单一时刻
```

用法：直接看 31/32 亮温和四组分温度的日变化；取 02:30、05:30、14:30、17:30 四个时刻，与 MOD11A1/MYD11A1 对比。

### A2　复用组分温度，Terra 过境的真实扫描角

| 项 | 与 A1 的差别 |
| --- | --- |
| 时间 | **单一时刻** 2019-08-15 02:30 UTC（Terra 上午过境） |
| 观测几何 | VZA、VAA **栅格**，取自该景 MOD03/MOD11_L2 的 SensorZenith/SensorAzimuth，重投影到同一 1 km 网格 |
| 热红外 | 组分温度 **文件**，选 A1 的 `components.json`（02:30 在序列中，直接取用） |
| 光学 | 可关闭 |

不重算能量平衡。得到的是带扫描角效应的 31/32 亮温，与 A1 的天底结果相减，就是角度效应图，扫描边缘可达数 K。

## 示例 B：Landsat 级 · 北京城区 30 m · 单一时刻

范围约 116.22–116.58°E、39.77–40.04°N（约 30 km × 30 km，约 1000 × 1000 像元），从老城区到奥林匹克森林公园，包括建成区、公园林地、水体、草地。规模与需求文档的“单景 1000 × 1000”目标一致。

### B1　ERA5 能量平衡，Landsat 过境

| 项 | 填写 |
| --- | --- |
| 地表 | 30 m 的 type（WorldCover/FROM-GLC 重分类为 IGBP）、LAI（Landsat 8 地表反射率估算，2019-08-13 至 08-20 合成）、DEM（SRTM 30 m）；土壤水分留空，取 ERA5 |
| 时间 | **单一时刻** 2019-08-15 02:55 UTC（北京 10:55，Landsat 8 path 123 / row 32） |
| 观测几何 | VZA 0°、VAA 0°（常数） |
| 光学 | Landsat 8/9 OLI B1–B7 |
| 热红外 | TIRS B10/B11；组分温度 **ERA5 能量平衡**，同一个 ERA5 包 |

注意两点：

- 整景大约只占 1–2 个 ERA5 格点，气象驱动几乎一样；城区与公园之间的温差完全来自地类、LAI、DEM。这正是 30 m 模拟要回答的问题，但结果页要明说“驱动为 0.25° 插值”；
- TIRS 的原始分辨率是 100 m，产品重采样到 30 m。和真实 B10 对比时，先把模拟结果聚合到 100 m 再比。

### B2　复用组分温度，模拟另一颗热红外载荷

| 项 | 与 B1 的差别 |
| --- | --- |
| 热红外 | 波段改为 SDGSAT-1 TIS 三个波段（约 9.35 / 10.8 / 12.0 μm，作为自定义波段输入）；组分温度 **文件**，选 B1 的 `components.json` |
| 光学 | 关闭 |

同一网格、同一时刻，不重算能量平衡，几秒内就能看到新载荷在同一场景下的亮温。这就是载荷论证的典型用法（结果仍是冠层顶，不含大气）。

## 1. 两个示例之间

- 两者网格不同，**组分温度文件不能互用**（首版不做重采样）；
- 两者共用一个 ERA5 包、同一天，B 的范围在 A 内。把 B1 的 30 m 结果聚合到 1 km，与 A 在 02:55 附近的结果比较，就是尺度效应，作为可选的分析，不做进界面。

## 2. 由示例确定的规则

**时间**

| 方式 | 填写 | ERA5 能量平衡 | 组分温度文件 |
| --- | --- | --- | --- |
| 单一时刻 | 日期 + 时刻（UTC，另显示当地时间） | 从当天 00 UTC 推进到该时刻 | 文件中须有该时刻 |
| 连续时间 | 起、止、步长（15 / 30 / 60 min，默认 60） | 从起始日 00 UTC 一次推进到终止时刻，逐时刻成像 | 文件中须包含区间内全部时刻 |

- ERA5 包须覆盖起始日 00 UTC 到终止时刻后 1 h，不足时运行前报出缺少的时次；
- 连续时间首版限制在 31 天以内。

**组分温度文件**

- 首选 `components.json`：记录时刻、网格和各时刻的 4 波段 `components.tif`，单一时刻和连续时间都能用；
- 单独一个 4 波段 `components.tif`（Tss、Tsh、Tcs、Tch，K）只能用于单一时刻，界面提示“未校验时刻”；
- 网格必须与地类栅格一致；
- 实测温度（站点、无人机）要先整理成 4 波段文件。

**观测角**：常数或栅格（与现在相同）。MODIS 用栅格，Landsat 用常数。

**热红外关闭时**：不显示温度来源，只做光学。

## 4. 工程配置草案

```jsonc
// A1
"time": { "mode": "series", "start": "2019-08-15T00:00:00Z", "end": "2019-08-15T22:00:00Z", "stepMinutes": 30 },
"view": { "vza": { "value": 0 }, "vaa": { "value": 0 } },
"thermal": { "enabled": true, "bands": [/* B31, B32 */],
  "temperature": { "source": "era5", "pack": "era5/era5-pack.json", "elevationCorrection": true } }

// A2
"time": { "mode": "instant", "at": "2019-08-15T02:30:00Z" },
"view": { "vza": { "file": "inputs/terra_0230_vza.tif" }, "vaa": { "file": "inputs/terra_0230_vaa.tif" } },
"thermal": { "enabled": true, "bands": [/* B31, B32 */],
  "temperature": { "source": "file", "file": "output/jjj_modis_1km_xxx/components.json" } }
```

兼容旧工程：`overpass` → `time.instant`；`temperature.mode = eb` → `source: era5`；`rt` + 组分温度文件 → `source: file`；`rt` + 手工四组分 → 打开时提示“已不支持手工组分温度，请选择组分温度文件或改用 ERA5”，不静默替换。

## 7. 落地前的缺口

| 项 | 情况 |
| --- | --- |
| A 的数据 | 齐全，需裁切 114.5–118.5°E、38.5–42°N 并处理 LAI 填充值 |
| B 的数据 | 地类、LAI、DEM、真实观测都有；**缺 2025-06-22 ERA5 逐小时** |
| B 的 LAI 空值 | 按地类补值（城市、水体取 0），否则一半像元不出结果 |
| 连续时间 | 引擎现在只算一个时刻；EB 的逐时推进已有，要加“请求时刻插入时次、逐时刻成像、分目录输出、`series.json`” |
| 读 `components.json` | 引擎现在只认 4 波段 tif；A2、B2 都靠这一条 |
| 夜间光学 | 太阳在地平线下时跳过光学并写 QA，A1 一半时刻是夜间 |
| 去掉手工输入 | 删除四组分常数、单组分栅格、24 波段逐小时栅格三种温度输入 |
