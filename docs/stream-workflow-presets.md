# STREAM 预设工作流：对统一表单的走查

状态：评审草案（2026-10-27），未改代码。用来检验 `stream-unified-workflow.md` 的“一张表单 + 温度三选一”能否支撑常见用法。依据：`stream.exe` 现有能力（`models/stream/README.md`）、内置示例 `assets/examples/landsat_beijing_eb`、`stream-lst-lsct-requirements.md`。

图例：✅ 表单与引擎都已支持 · 🟡 表单能表达，但缺一个便利功能或需要约定 · 🔧 需要修改表单设计 · ⛔ 引擎没有，本轮不做

## 1. 预设清单与结论

| # | 工作流 | 温度来源 | 要填的输入 | 结论 |
| --- | --- | --- | --- | --- |
| W1 | 光学 BRF 模拟 | —（热红外关闭） | 地类、LAI、过境时刻、VZA/VAA、光学预设 | ✅ |
| W2 | 已知组分温度 → 方向亮温 | 给定（常数或栅格） | W1 + 热红外预设 + 四组分温度 | ✅ |
| W3 | ERA5 驱动单日能量平衡（北京示例） | 能量平衡 | W1 + 热红外预设 + ERA5 包；土壤水分留空即取 ERA5 | ✅ |
| W4 | 复用 EB 结果，只改角度或波段 | 给定（组分温度文件） | W2，温度文件选上次 EB 输出的 `components.tif` | 🟡 缺“用此结果作为组分温度”的一键操作 |
| W5 | 多角度方向亮温（热红外角度效应） | 给定 / 能量平衡 | W2/W3 + **多个视角** | 🔧 当前一次只有一个视角 |
| W6 | 传感器论证（比较 Landsat、SLSTR、MODIS 波段） | 任一 | 换波段预设或改波段表 | 🟡 只到冠层顶，无大气、PSF 和噪声 |
| W7 | 城市热环境 | 给定 / 能量平衡 | 地类含 13（城市） | ✅ 按不透水面 + 绿地四组分简化 |
| W8 | LST 单景（Landsat B10/B11） | 由观测反演 | W2 的结构输入 + 观测亮温（2 波段） | 🔧 观测亮温必须约定为地表亮温；分裂窗需要水汽 |
| W9 | LSCT 双视角（SLSTR 天底 + 倾斜） | 由观测反演 | 2 个视角 × 各自的观测亮温 | 🔧 依赖 W5 的视角列表 |
| W10 | 以能量平衡为先验的反演 | 由观测反演（先验 = 能量平衡） | W8/W9 + ERA5 包 | ✅（设计内；反演后端待接） |
| W11 | OSSE 自检：正向 → 加噪 → 反演 → 与真值对比 | 先“给定”，再“由观测反演” | W2 的输出作为观测，原组分温度作为真值 | 🟡 缺“用此结果作为观测”和可选的真值字段 |
| W12 | 日变化 / 多时刻 | 能量平衡 | 一串过境时刻 | ⛔ 现在一次运行只算一个时刻；可分次运行，但每次都从 00 UTC 重算 EB |
| W13 | 时间序列同化（静止卫星、多日） | — | 多日观测 + EB 时间模型 | ⛔ 不在本轮（WP4） |
| W14 | 森林高度/密度、坡度坡向 | — | 结构与地形栅格 | ⛔ 引擎未接入；在引擎接入前表单不显示 |
| W15 | 由光学反演 LAI | — | 光学反射率观测 | ⛔ 本轮反演只做 LST/LSCT；LAI 只作输入 |

**结论：** 15 个工作流中，一张表单能直接覆盖 W1–W4、W6、W7、W10（共 7 个），其中 W4、W6 只差便利功能或说明。真正逼出设计修改的有三处（W5、W8、W9），W11 还需要两个结果页按钮；W12–W15 是引擎或范围问题，与表单设计无关。

## 2. 逐个走查（只列关键步骤）

**W1 光学 BRF：** 位置与时刻 → 观测几何 → 地表（地类、LAI）→ 光学预设 → 关闭热红外 → 运行。热红外关闭后不再显示温度选项，这一点比现在的界面短（现在仍要先选 RT/EB 模式卡）。

**W2 已知组分温度：** 在 W1 基础上打开热红外，温度来源选“给定”，四组分各填常数。默认值 315/303/305/300 K 能直接跑通。

**W3 能量平衡：** 温度来源选“能量平衡”并选 ERA5 包。土壤水分规则：地表输入里留空就取 ERA5 `swvl1`，填写则用填写值。内置北京示例的 `soilMoisture.source = "era5"` 读入后正好等价于“留空”，行为不变。

**W4 复用 EB：** 现在需要手工到输出目录找 `components.tif`。补充：结果页加 **“用作组分温度”** 按钮，把温度来源切换为“给定 → 组分温度文件”并填好路径。引擎已支持，只改界面。

**W5 多角度：** 现在观测几何只有一对 VZA/VAA（可以是常数或栅格），要看角度效应只能改角度跑多次。见 §3.1。

**W8 LST 单景：** 这是暴露问题最多的一个：
- STREAM 输出的是**冠层顶**亮温，没有大气。卫星 L1 亮温是大气层顶亮温，直接当观测会把大气误差全算进温度；
- 需求文档把 LST 基线定为**分裂窗**，分裂窗输入的是大气层顶亮温加水汽，与可微反演不是同一种观测；
- 单视角 2 波段时，LSCT 欠定，只能由先验主导。

处理见 §3.2。

**W9 SLSTR 双视角：** 需要两组几何和两份观测亮温。单个“观测亮温文件”字段表达不了，见 §3.1。

**W11 OSSE：** 先用“给定”跑出 `tir_brightness_temperature.tif`，再切换到“由观测反演”，把它作为观测。补充：结果页加 **“用作观测”** 按钮；高级设置里加可选的 **“真值组分温度”** 字段（填写后额外输出误差图和 RMSE）。这样不必离开工作台就能做可识别性检验，也符合 README 里“先 OSSE 再上真实卫星”的路线。

## 3. 由此带来的设计修改

### 3.1 观测几何改为“视角列表”（解决 W5、W9）

```
观测几何
  视角 1   VZA [0 ]°  VAA [0  ]°   （常数或栅格）   观测亮温 [ 仅反演时显示 ]
  视角 2   VZA [55]°  VAA [180]°                     观测亮温 [ ... ]
  [+ 添加视角]
```

- 默认只有一个视角，界面与现在完全一样；
- 正向：每个视角各输出一份亮温/方向温度（文件名加 `_v1`、`_v2`）；
- 反演：观测亮温从“温度来源”里移到每个视角的行内，因为观测本来就跟视角绑定。“由观测反演”下只剩先验与高级设置；
- 引擎：EB 求出的组分温度与视角无关，只需要在成像阶段循环视角，计算量很小；配置把 `view` 扩展为 `views: [...]`，单个 `view` 继续兼容。

### 3.2 反演的观测口径（解决 W8）

首版反演明确：**观测 = 地表（冠层顶）亮温**，即已做过大气校正的亮温，界面字段直接叫“地表亮温（已大气校正）”。

- LST 产品的分裂窗基线放在第二步，作为“由观测反演”下的一个方法选项（`方法：物理反演 | 分裂窗`）。选分裂窗时观测改为大气层顶亮温，并复用 ERA5 包提供水汽；
- 单视角时，输出页对 LSCT 显示“先验主导”的 QA 标记；LST 正常输出；
- 大气 LUT（WP1）接入后，观测口径再加一个“大气层顶”选项，表单结构不变。

### 3.3 结果页增加两个按钮（解决 W4、W11）

| 按钮 | 作用 |
| --- | --- |
| 用作组分温度 | 有 `components.tif` 时出现 → 温度来源切换为“给定 → 文件” |
| 用作观测 | 有亮温产品时出现 → 温度来源切换为“由观测反演”，按视角填好观测文件 |

### 3.4 新建工程模板

上面的预设做成“新建工程”时的模板，**只是预填表单，不是模式**。建议放 6 个：

1. 光学 BRF（W1）
2. 已知组分温度 → 亮温（W2）
3. ERA5 能量平衡（W3，即北京示例）
4. 多角度方向亮温（W5，预填天底 + 55°）
5. LST/LSCT 单景反演（W8）
6. SLSTR 双视角 LSCT（W9）

反演模板（5、6）在后端接入前不显示。

## 4. 修改后，表单只多了这些

| 位置 | 新增 | 何时显示 |
| --- | --- | --- |
| 观测几何 | “添加视角” | 始终（默认 1 个视角） |
| 每个视角 | 地表亮温文件 | 温度来源 = 由观测反演 |
| 温度来源 · 由观测反演 | 先验（自动/能量平衡）、高级（误差、迭代、真值） | 同上 |
| 结果页 | 用作组分温度、用作观测 | 有对应产品时 |

没有新增模式，也没有新增与反演无关的必填项。

## 5. 待确认

1. 视角列表放进第一步（纯界面，加上引擎成像循环），还是放到反演那一步？W5 多角度正向本身就有用，建议放第一步。
2. 首版反演只接受地表亮温（已大气校正）是否可以？分裂窗放到第二步作为方法选项。
3. OSSE 的“真值”字段放在高级设置里，还是只在“用作观测”时自动带入？
4. 日变化（W12）是否需要？如果需要，最小做法是“过境时刻”允许填多个，EB 只从 00 UTC 算一遍、逐个时刻成像，这同样是引擎里的小改动。
