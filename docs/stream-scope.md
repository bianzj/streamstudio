# STREAM 工作范围与职责边界

状态：定位草案（2026-10-27）。用于明确 STREAM 在 Stream Studio 中“做什么、不做什么”，以及近期工作包。

## 1. 一句话定位

- **HiStream**：三维场景的高保真正向模拟与**样本生成**；STREAM-NET 在其亮温结果上做前向残差修正。
- **TiRT / TIRTEB**：单点/单像元的正向与反演算法研究、参数敏感性、算法验证；单点工作在这里开展。
- **STREAM**：把 TiRT/TIRTEB 验证过的单点算法扩展到**整景影像**，负责栅格 I/O、逐像元并行、空间约束、邻域/大气/几何配准、批量与时序、QA/不确定性、产品与界面。LST 用分裂窗等基线生成，LSCT 用可微正向链 `H(x)` 反演。
- **STREAM-NET 不是反演器**：它是 HiStream 样本上的前向偏差修正/代理，服务于“样本更接近观测”，不直接输出地表参数。

## 2. STREAM 的核心工作

### A. 正向模拟（已有）

给定地类、LAI、土壤水分、DEM、观测几何、波段、过境时刻和 ERA5，输出：

- 光学方向反射率（BRF）；
- 热红外亮温/方向温度；
- 四组分温度；
- EB 的净辐射、显热、潜热、土壤热通量与诊断。

当前实现：`models/stream`，已按 TiRT/TIRTEB 对齐（hom3 节点辐射度、热点、气动/气孔、7 h 表面热历史、1/L 割线等）。边界：均匀冠层/裸地、像元级、冠层顶、无大气。

### B. LST 基线与 LSCT 反演（核心增量）

- **LST**：用分裂窗（双 TIR 波段）或单通道 + 大气校正做产品基线；STREAM 负责影像级实现、发射率/水汽/云 QA、误差传播、批量与时序，不做可微反演。
- **LSCT**：给定多角度/多时相/多波段亮温与先验，反演四组分温度 Tss/Tsh/Tls/Tlh；LAI、土壤水分、发射率作为输入/先验，不作为本轮反演变量。方法为变分同化（Gauss–Newton / L-BFGS），梯度来自可微正向链或伴随；EB 用隐式微分或弱约束；后验不确定性用 Laplace 近似或集合方法。SW 的 LST 可作为等式约束或初值。

当前进度：`tools/stream-inverse` 单像元原型，autograd 梯度校验通过；LAI/有效温度可识别，单个晴/阴组分温度仅靠多波段亮温条件数高，需要光学 BRF、多角度或先验。LST 的分裂窗基线尚未实现。

### B2. 植被结构约束与卫星同化

- **植被结构作为输入/先验**：LAI、覆盖度、冠层高度、叶宽/叶倾角、聚集指数、热点；STREAM 当前是均匀冠层 + 球面叶倾角，无聚集指数和垂直廓线，HiStream 提供三维校验；
- **不把结构作为主反演变量**：单靠 TIR 无法反演结构；若联合，只更新低维有效参数（有效 LAI/聚集指数），并加先验和时间平滑；
- **结构误差传播**：进入 LST/LSCT 的不确定性，不能当无误差真值；
- **单景迭代反演**：结构固定，变分反演 LST/LSCT；
- **时间序列同化**：状态为 LST/LSCT + 土壤温度/水分（可选慢变结构），EB 作时间模型，EnKF/4D-Var 同化极轨/静止卫星观测；
- **正向能力测试**：先用 TiRT/TIRTEB 单点、HiStream 三维样本、UAV/站点验证正向 BRF/BT/LST/LSCT，再做结构敏感性试验，确认均匀冠层近似的适用边界。

### B3. 正向能力测试

- 单点：与 TiRT/TIRTEB 对照 BRF/BT/组分温度/通量；
- 三维：与 HiStream 样本对照，检查热点、方向亮温、阴影/光照比例；
- 影像：与 UAV/航空/卫星晴空像元对照；
- 敏感性：LAI、高度、叶倾角、聚集指数、热点、土壤水分；
- 记录偏差边界，作为反演模型误差的先验。

### C. 样本—验证闭环

- HiStream（+STREAM-NET）生成带真值的“参数—观测”样本；
- STREAM 用这些样本标定/验证反演，做 OSSE；
- STREAM-NET 作为正向残差修正，可放在反演的观测算子之后，或作为代理加速；
- 真实卫星数据用于最终精度评估。

## 3. 明确不做（由 HiStream 或其他模块承担）

- 三维几何、遮挡、树冠/建筑内部结构、面元/体元辐射传输；
- 三维场景的样本生成与高保真成像；
- 植被生长、碳/水收支、EnKF 之外的生态系统过程；
- 完整的城市多组分（当前 STREAM 为不透水面 + 绿地四组分简化）；
- 大气订正算法本身（可接 LUT 或外部大气产品，但不在 STREAM 内重写 MODTRAN）。

## 5. 需要先拍板的问题

1. **主产品是什么**：模拟影像（正向）为主，还是参数反演图（反演）为主，还是两条产品线并列？
2. **首个反演目标**：单波段 TIR 的 LST/组分温度（较稳），还是 LAI/土壤水分/发射率联合反演（信息量要求高）？
3. **观测源与大气**：Landsat、Sentinel-2/3、UAV，还是先做 OSSE；大气用 LUT 还是外部产品？
4. **实现形态**：反演放在 `stream.exe`（C++/有限差分或 AD），还是独立 Python/JAX 服务（与 `models/stream` 共用常量/光谱）？
5. **STREAM-NET 的位置**：仅做前向残差修正，还是也训练成反演初值/代理？这决定样本格式与训练目标。

## 6. 建议的近期路线

1. 先把**单像元反演原型**补齐光学 BRF 与不确定性，完成 OSSE；
2. 选一个明确产品（建议先做“组分温度/LST 反演”）；
3. 再做多像元矢量化与 HiStream 样本批量验证；
4. 最后接真实卫星数据与工作台“反演”模式；
5. 时间同化与 STREAM-NET 接入放在产品链路稳定之后。

## 7. 用户与需求假设（待验证）

> 目前没有外部用户使用数据，也没有埋点；以下是基于仓库定位、示例和文档做出的假设，必须用访谈/试点验证，不能当成结论。

### 7.1 可能的用户分层

| 用户 | 典型场景 | 真正需要的东西 | 与当前产品的匹配 |
| --- | --- | --- | --- |
| 定量遥感科研人员/研究生 | 热红外方向性、组分温度、LAI/SM 反演、算法验证 | 可控物理、可复现实验、批量跑、误差/不确定性、能写论文的验证 | 物理匹配度高；缺反演产品、批量、验证报告 |
| 农业/林业/生态应用 | 作物长势、旱情、森林结构、时间序列 | 现成产品、精度指标、GIS/GeoTIFF、少调参 | 当前参数太多、无业务化精度承诺 |
| 城市热环境/规划 | 地表温度、建筑—绿地混合像元、热岛 | 城市组分温度、下垫面分类、专题图 | STREAM 城市是四组分简化；HiStream 更合适但慢 |
| 载荷/传感器论证 | 波段选择、噪声/PSF/大气影响、场景仿真 | 前向模拟、传感器模型、样本生成 | 正向可用；缺大气/PSF/噪声链 |
| 教学与内部样本 | 课程演示、HiStream/STREAM-NET 样本 | 可重复案例、清晰工作流、稳定结果 | 示例和 GUI 较好；缺教学任务包 |

### 7.2 用户一般要什么（共性）

1. **一个明确产品**：不是“能算很多量”，而是“给我 LST/LAI/SM 图，精度多少”。
2. **默认可用**：用 Landsat/Sentinel + ERA5 + DEM + 地类就能跑，不需要理解 EB、气动、节点辐射度。
3. **批量与时序**：一个区域、一年、多个过境，而不是一次一景手工点。
4. **不确定性与 QA**：哪些像元可信、为什么被云/水体/饱和/不收敛剔除。
5. **数据兼容**：GeoTIFF/NetCDF、常见投影、中文路径、ERA5 下载/登记、GIS 导出。
6. **可验证**：与站点、UAV、SCOPE、其他产品对比的报告和指标。
7. **可引用/可交付**：方法说明、版本号、参数快照、结果可复现。

### 7.3 STREAM 的差异化

不与业务化 LST/LAI 产品比“全球全自动”，而是打**异质场景 + 物理可解释 + 不确定性 + 三维样本闭环**：

- 四组分（光照/阴影土壤、叶片）温度，而不是单一 LST；
- 方向亮温/多角度，解释热红外角度效应；
- 城市/森林/农田的组分混合，HiStream 样本可校验；
- 反演给出后验不确定性，而不是只给一张图；
- 与 HiStream/STREAM-NET 的样本链结合，形成“仿真—反演—验证”闭环。

### 7.4 建议的首个滩头

**热红外组分温度/方向亮温反演**，面向有 UAV/多角度或站点验证数据的科研团队：

- 输入：Landsat 8/9 或 Sentinel-3 单景 + ERA5 + DEM + 地类 + LAI（可选）；
- 输出：Tss/Tsh/Tls/Tlh、LST、方向亮温、不确定性、QA；
- 验证：UAV/站点/多角度观测；
- 形态：先 Python API/CLI，再进工作台；不要求用户调物理参数。

之后再扩到 LAI/土壤水分联合反演和农业/生态应用。

### 7.5 需求验证（先做，不先扩功能）

1. 找 5–10 位目标用户访谈：手上有什么数据、现在怎么做、最缺哪张图、精度门槛、愿不愿意试用。
2. 选 2–3 个试点：一个科研组、一个应用单位、一个教学/内部样本场景。
3. 用同一景数据做端到端演示，记录：能否跑通、耗时、精度、用户愿不愿意继续用。
4. 设定成功指标：试点场景数、重复使用次数、验证 RMSE、产出报告/论文/业务图件。
5. 没有 2–3 个明确试点承诺前，不继续加物理模块和界面功能。
