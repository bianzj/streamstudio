# RayTracing 模式降方差：Owen 置乱 Sobol 采样与相关修正

范围：`eRaytracing`（硬件光追路径追踪，`shader/RayTracing/offline.rgen`）。其他模式不受影响。

## 1. 开关与默认值

| 设置 | 取值 | 默认 | 说明 |
|---|---|---|---|
| 环境变量 `HISTREAM_RT_SAMPLER` | `legacy` / `sobol` | `sobol`（2026-11-26 起） | 其他值直接报错。优先于工程文件 |
| 环境变量 `HISTREAM_RT_SEED` | 整数 | 0 | 写入推送常量 `RayRTSetting::frame`，改变逐像元随机序列。0 = 历史序列 |
| 工程 `control.adaptiveSampling` / 环境变量 `HISTREAM_RT_ADAPTIVE` | `true`/`false`；`1`/`0` | 关 | 方差自适应采样（实验性，见 §11：实测没有收益，保持关闭）。需要 sobol；`HISTREAM_RT_ADAPTIVE_SCOUT`（侦察样本占预算的比例，默认 0.25）、`HISTREAM_RT_ADAPTIVE_TILE`（σ 平均的 tile 边长，默认 1）仅供实验 |
| 环境变量 `HISTREAM_RT_MAX_WAVE` | 整数 | 自动 | 强制逐线程数组容量（实验用，见 §10；不会小于波段数） |
| 工程 `control.sampler` | `"legacy"` / `"sobol"` | `"sobol"` | 未知字符串回退到默认值。界面没有对应控件（见 §7），需手工写入 JSON；`normalizeProject` 与统一工程互转都保留该字段 |
| 工程 `control.seed` | 整数 | 0 | 同上 |

- **默认 `sobol`（2026-11-26 起）**。`legacy`（环境变量或 `control.sampler`）与旧引擎**逐位相同**（见 §4），在默认值为任何一种时都能复现旧结果。默认值只在一处定义：`src/base/structs.h` 的 `kRaytracingDefaultSampler`（0 = legacy，1 = sobol）；工程字段缺省与 `RaytracingIO` 都用它。Sobol 改变每个像元的随机序列（不再有“第 0 个样本固定在像元中心”），与旧结果只在统计意义上一致（§9 给出默认路径与旧采样高采样参考的偏差）。
- 采样器通过着色器特化常量 8 选择（`pipeline.cpp`），选 `legacy` 时驱动在建管线时折叠掉全部 Sobol 分支，生成的代码与旧版一致，这是 legacy 能逐位一致的原因（直接用运行时分支会使约 0.01% 像元因舍入级差异而路径分叉）。
- 使用 `HISTREAM_RT_SEED` 时，引擎日志会打印 `raytracing: sampler …, seed …`。

## 2. 采样器做了什么

`shader/RayTracing/sampler_qmc.glsl`：Burley 2020（JCGT 9(4)）的哈希 Owen 置乱 Sobol。每个“点对”先对样本序号做嵌套均匀置乱，再取 Sobol 第 0/1 维并各自 Owen 置乱，种子为 `hash(像元种子, 点对编号)`，不同点对、不同像元互相独立。样本编号即 `kSample`（`n_sample` 不必是 2 的幂；前 2^k 个样本构成 (0,k,2)-网）。

维度分配（`QMC_VERTEX_DEPTH = 2`，即前两个散射顶点；其余回到原 PCG）：

| 点对 | 用途 |
|---|---|
| 0 | 像元内抖动（Sobol 模式不再固定第 0 个样本在像元中心） |
| 1+3d | 顶点 d 的天空 NEE 方向 |
| 2+3d | 顶点 d 的散射方向 |
| 3+3d | 顶点 d 的（俄罗斯轮盘赌，反射/透射选择） |

原 PCG 抽样（含两次遗留的景深抽样）始终照常执行，Sobol 模式只是覆盖其中的值，所以随机序列与旧版对齐。

## 3. 其他改动

1. **太阳阴影射线省略**（`offline.rgen`，`DirectLighting`）：太阳在表面背侧、材料各波段 T = 0、且没有热红外波段（向阳/背阴温度要用阴影结果）时，太阳项恰为 0，不发阴影射线。逐位不变（已核对）。在本次用的小场景上耗时差异小于测量误差，**不能宣称有实测加速**。
2. **非有限样本的根因已修复**（见 §8）：`sampling.glsl` 的余弦半球采样在 r 贴近 1 时对负数开根号得到 NaN 方向。现在 RayTracing 着色器定义 `RT_SAFE_COSINE_SAMPLING`，取 `sqrt(max(·, 0))`；体元着色器不定义该宏，SPIR-V 不变。着色器里仍保留“丢弃非有限样本”作为最后一道防线，但会在输出缓冲末尾的计数器上加 1，主机读回后若大于 0 会在 stderr 打印 `WARNING raytracing: N non-finite path sample(s) were dropped …`。修复后 rt_crop / rt_urban 上该计数始终为 0。
3. **提交切片下限**（`src/raytracing/command.cpp`）：原先按 120 ms 自适应切分时，高采样数下会缩到每次只提交 1 行（约 1000 个线程），GPU 吃不满。现在每次至少约 32k 像元。结果不依赖切片大小（逐位相同，已核对）。1024² 像元、1024 采样：legacy 4.8 → 3.35 s，Sobol 38 → 4.1 s（含约 0.85 s 启动）。
4. 种子打通：`setting.frame` 此前主机端从未写入，所有运行、所有观测角的随机序列完全相同。

**没做**：Planck 缓存（热红外波段数少，收益小）；以主波段为准的反射/透射选择 + 光谱 MIS（叶片 R≈0.07、T≈0.04 时该选择造成的通量相对波动只有约 0.27，上限收益很小，没有做偏差核对的必要）；热红外天空并入 NEE。

## 5. 已知限制与诚实说明

- 近红外波段（842 nm）只改善 1.2–1.7×：该波段由深层多次散射主导，随机性主要在路径后段，当前的维度分配对它帮助有限。
- 改善集中在“像元内几何覆盖”的方差（边缘、冠层缝隙）；阴影射线、太阳项本身是确定的，不会因 Sobol 改变。
- Sobol 采样器不提供屏幕空间蓝噪声分布；各像元噪声互相独立（白噪声）。
- 两个场景都很小，GPU 极快，结论只在这两个场景上测过；较重的场景（`002-rainforest` 等）没有测。
- 工程界面尚无“采样器/种子”字段；`control.sampler`、`control.seed` 只能手工写入 JSON（它们不会被服务端规范化丢弃，见 §7）。

## 8. 非有限样本的根因（排查记录）

现象：legacy 在 `rt_crop` 上 256/1024 采样时约 20% 的运行出现一簇 6–9 个相邻像元，热红外亮温被替换成 84–290 K；可见光波段看起来正常。

定位过程：
1. 逐步排除：丢弃“Radiance 或 Throughput 非有限”的样本就能消除（把检查限制在某一个波段也一样，说明整条路径的通量都坏了）；丢弃“Radiance 极大”的样本无效，说明不是萤火虫而是 NaN/Inf。
2. 簇状的原因：`outputOrth` 对原始图像做双线性重采样，一个原始像元为 NaN→0→被当作天空值替换，会扩散成约 3×3 个输出像元。
3. 在着色器里按阶段记录第一个非有限量（临时调试版，已删除），并临时在主机端扫描原始（重采样前）输出：被毒化的像元 (199, 72) 的记录是“BSDF 采样得到的方向 wi 非有限”：wi = (0.00788654, −0.999969, **NaN**)，pdf = NaN，bsdf0 = −1/π。wi.xy 有限、|wi.y| ≈ 1，即 r ≈ 1。
4. 机理：`sampleHemisphereCosine`（`sampling.glsl`）里 z = `sqrt(1 − r²cos²φ − r²sin²φ)`，r = |r1| 或 |r2| 贴近 1（`Rnd()` 可以恰好返回 1.0）时，浮点舍入使根号内为微小负数，得到 NaN。NaN 方向使该顶点之后的 Throughput 全部变成 NaN；NaN 方向的光线判为未命中，二次射线逃逸分支只对热红外波段累加 `Throughput × Planck(天空)`，于是只有热红外波段被毒化，可见光波段（天空短波只走 NEE）侥幸不受影响。Sobol 模式的 `qmcCosineHemisphere` 本来就有 `max(0, ·)`，所以 Sobol 路径在此不受影响。

修复后的验证（`rt_crop` 256²、6 波段；`rt_urban` 256²、3 波段）：
- 把修复关掉、保留计数器：种子 100–139、256 采样，crop 8/40 次运行各丢弃恰好 1 个样本，urban 6/40 次；约每 1.2×10⁻⁸（crop）/ 9×10⁻⁹（urban）个样本出现 1 次。
- 打开修复：crop 256² 256 采样 × 40 种子、1024 采样 × 32 种子、1024² 1024 采样 × 12 种子（合计约 1.6×10¹⁰ 个样本）丢弃 0 个；urban 256² 256 采样 × 40、1024 采样 × 32、1024² 1024 采样 × 6（约 6.4×10⁹ 个样本）0 个；Sobol 模式 crop 30 次 + urban 30 次（1024 采样）0 个。关闭修复时同样规模的期望值分别约 190 与 58 个。
- 未命中该问题的输出与基线引擎逐位相同（crop 256² 16 采样含/不含热红外、crop 1024² 64 采样、urban 256² 16 采样、urban 仅可见光 1024² 128 采样；MD5 一致）；只有出现过 NaN 样本的像元（原先被替换成天空值）会变成正常值，影响 ≈ 每 10⁸ 个样本 1 个。
- 体元着色器：`voxelrt/voxelrad_diffuse_single.comp`、`voxelrt/voxelrad_image.comp`、`voxeleb/voxelrad_scattering_VNIR.comp`、`voxeleb/voxelrad_diffuse_TIR_single.comp`、`voxeleb/voxelrad_image.comp`、`voxeleb/voxelrad_solar.comp` 在改动前后编译出的 SPIR-V 逐字节相同（只有 RayTracing 定义宏）。这些着色器并不调用该采样函数（见 §9），所以没有同样的风险。
- Sobol 方差行复核：`rt_crop` 16 采样 K = 24，legacy 与 sobol 的 24 幅图与修复前逐位相同（最大差 0），§4 的方差表无需更新。

萤火虫（有限但很大的样本）：用临时计数版统计 `rt_crop` / `rt_urban` 256² 256 采样（各约 1.7×10⁷ 个样本）中单样本 HDRF（π·L/E_ref，可见光与近红外各波段取最大）超过阈值的个数：> 1：46516 / 30151；> 2：1868 / 732；> 5：0 / 0（阈值 10、50、200 也都是 0）。即单样本 HDRF 最大值在 2–5 之间，这两个场景没有同源的萤火虫；修复只改变了原先的 NaN 样本，不改变有限样本，所以“修复前/后”的有限样本最大值相同。
## 9. 默认改为 Sobol 后的复核（2026-11-26）

- **legacy 仍逐位复现旧结果**（MD5 与旧基线引擎相同）：`HISTREAM_RT_SAMPLER=legacy` 与 `control.sampler="legacy"` 在 `rt_crop` 256² 16 采样与 `rt_urban` 256² 16 采样上均相同；不设置时输出与显式 `sobol` 逐位相同，与基线不同。
- **默认（Sobol）与旧采样高采样参考的偏差**（参考 = legacy 1024 spp × 24 个种子（`rt_urban` 为 8 个）；默认路径 24 个种子（urban 16 个），相对偏差 %，括号内为 z 值）：
  - `rt_crop` 16 spp：475/560/668/717 nm −0.0003/−0.0006/−0.0004/+0.0005，842 nm +0.0046，10.5 µm −0.0001；64 spp：+0.0021/+0.0022/+0.0017/+0.0041，842 nm +0.0086，10.5 µm 0.0000；256 spp：+0.0019/+0.0020/+0.0017/+0.0028，842 nm +0.0025。全部 |z| ≤ 2.5。
  - `rt_urban` 16 spp：660 nm +0.0041，860 nm +0.0117（z = 1.8），10.5 µm −0.0002；64 spp：+0.0013/+0.0057/0.0000。
  - 可见光偏差 ≤ 0.004%，近红外最大 0.012%，都在噪声范围内（参考本身也只有 8–24 个种子，且旧采样在低采样数下有约 −0.01% 至 −0.04% 的中心样本偏差）。
- **耗时**（含约 0.75 s 进程启动，4 次取最小）：`rt_crop` 1024²：256 spp 1.15 → 1.25 s，1024 spp 2.89 → 3.97 s（纯计算约 +50%）；`rt_urban` 1024²：256 spp 1.04 → 1.05 s，1024 spp 2.05 → 2.04 s；256² 16 spp 两者都约 0.75 s。
- **`rt_forest` 质量档位**重标：见用户手册 13.2.1。
- **体元路径里有没有同一个 `sqrt`？** 核对结果：没有。`sampleHemisphereCosine(inout uint seed)`（`shader/sampling.glsl:254`，其中 `sqrt(1-r*r*cosPhi*cosPhi-r*r*sinPhi*sinPhi)` 在第 287 行）只被 `bsdf.glsl:84` 的 `SampleBSDF` 调用，而 `SampleBSDF` 的调用者只有 `shader/RayTracing/offline.rgen`（已修）和不参与编译的旧着色器 `shader/cases/RayTracing_Lambert|Hapke/offline.rgen`；`voxelrt/`、`voxeleb/`、`facetrt/`、`faceteb/` 的着色器虽然 `#include` 了 `bsdf.glsl`/`sampling.glsl`，但没有调用这些函数（对 `SampleBSDF`、`sampleHemisphereCosine`、`SampleHemisphereCosine`、`sampleHemisphereCosineConcentric`、`samplingHemisphere`、`sampleDisk` 的全文检索无命中）。`sampling.glsl` 里另有两个同类写法但无人调用的函数：`SampleHemisphereCosine(vec2)`（第 192 行，`sqrt(1.0 - d.x*d.x - d.y*d.y)`）与 `sampleHemisphereCosineConcentric(vec2)`（第 199 行），将来被体元代码调用前应同样加 `max(·, 0)`。体元着色器自己的方向采样（`voxelDirs` 等）不在本次范围内，未检查。

## 10. 逐线程数组按波段数定容（2026-11-26，不改数值）

- 改动：`offline.rgen` 的 `Radiance`/`RadianceSum`/`Throughput` 原来固定 800 个 float（约 9.6 KB/线程，会溢出到本地内存）。容量改为特化常量 9（`RT_MAX_WAVE`），主机（`pipeline.cpp`）取 {16, 32, 64, 128, 800} 中不小于波段数的最小值；循环仍用 `setting.n_wave`；`HISTREAM_RT_MAX_WAVE=<n>` 可强制容量。
- **逐位不变**：与此前引擎（`engine2` 快照）的 MD5 对比，两种采样器下 `rt_crop` 6 波段、`rt_urban` 3 波段（256² 16 采样）以及 1/3/8/12/20/80/100 波段的 `rt_crop` 全部相同。
- **下限取 16 而不是 8**：容量 8（6 波段、3 波段的 `rt_crop`/`rt_urban` 自动取到）会让驱动换一种浮点收缩，输出相对差 ≤ 6×10⁻⁷（约 15%/4% 的数值不同，场景均值差 1×10⁻⁷），并且在 `rt_crop` 上更慢（1024²、1024 采样净耗时 2.84 → 3.53 s）。容量 ≥ 16 全部逐位相同。
- **加速很小**（1024² 像元，best-of-5，净耗时 = 总墙钟 − 1 采样的墙钟）：

| 算例 | 采样数 | 旧（800） | 新（自动） | 变化 |
|---|---|---|---|---|
| `rt_crop` 6 波段 | 256 | 0.42 s | 0.42 s | 0% |
| | 1024 | 2.94 s | 2.82 s | −4% |
| `rt_urban` 3 波段 | 256 | 0.19 s | 0.20 s | +5% |
| | 1024 | 1.20 s | 1.19 s | −1% |
| `rt_crop` 80 波段 | 64 | 0.69 s | 0.80 s | +16%（噪声） |
| | 256 | 6.32 s | 6.32 s | 0% |

  即在这块显卡上全部在测量误差内：数组放不放得进寄存器不是瓶颈（80 波段时容量 128 与 800 没有差别）。保留是因为它零风险、逐位不变，且减少本地内存占用，对显存/占用率更紧的显卡可能有用。80 波段场景的墙钟 3.9 s 启动时间不在这个函数里。

## 11. 方差自适应采样（可选，默认关闭，不推荐）

**设计**（`offline.rgen` 的 `AdaptivePass`、`raytracing.cpp` 的 `Raytracing::trace`，特化常量 10 = `RT_ADAPTIVE`，关闭时代码被折叠，常规路径逐位不变）：
1. 侦察遍：每像元 25% 预算的样本，使用与正式样本不同的种子（PCG 与 Sobol 都换），算出单样本相对标准差 σ（各波段相对标准差的均方根，再并入样本落空比例的伯努利项，全落空取 0.5）。侦察样本不进入结果。
2. 主机读回 σ，二分求缩放系数，使每像元样本数 clamp(round(s·σ), 预算/4, 预算×4) 的平均等于预算（可选 tile 平均 σ，让同一 warp 的线程样本数一致）。
3. 正式遍：每像元 n_i 个样本，用常规种子，Sobol 序号 0 … n_i−1 连续（分层保持）。因为估计只用与分配无关的样本，分配对估计**无偏**；样本数均匀时与常规路径逐位相同。
- 需要 sobol：legacy 采样器把第 0 个样本固定在像元中心，样本数逐像元不同时会产生偏差（实测 16 采样 +0.2%），所以 legacy 下请求自适应会被忽略并警告。少于 8 采样时也忽略。
- 一个走过的弯路：第一版直接把先导样本并入最终均值，分配依赖先导样本，实测有偏（16 采样可见光 +0.4%，近红外 −0.5%；64 采样 +0.06%、−0.29%），已废弃。

**结果**（`rt_crop` 256²，K = 24 个种子，参考 = legacy 1024 spp × 24；“相对方差”= 逐像元方差/参考²，对像元取平均；总样本数含侦察，即自适应预算 N 对应固定采样 1.25 N）：

| 预算 N | 指标 | 固定 N | 固定 1.25N | 自适应 N（含侦察） |
|---|---|---|---|---|
| 16 | 相对方差 ×10⁻³（475/560/668/717/842 nm） | 1.32/1.20/1.67/1.31/4.92 | 1.14/1.03/1.44/1.11/4.00 | 1.48/1.35/1.83/1.55/7.21 |
| | 绝对方差 ×10⁻⁶（同上） | 2.29/4.94/8.34/18.3/237 | 1.98/4.23/7.24/15.4/193 | 3.87/7.67/15.0/26.6/341 |
| 64 | 相对方差 ×10⁻³ | 0.198/0.184/0.245/0.222/1.14 | 0.164/0.152/0.204/0.181/0.911 | 0.124/0.115/0.157/0.165/1.29 |
| | 绝对方差 ×10⁻⁶ | 0.350/0.777/1.24/3.32/55.9 | 0.289/0.641/1.03/2.71/44.7 | 0.415/0.864/1.55/3.73/66.8 |
| | 相对偏差 % | +0.002…+0.009 | +0.004…+0.009 | +0.002…+0.004 |

- 同样总样本数下：64 采样时可见光相对方差好 1.1–1.3×（相对固定 1.25N），其余指标——近红外（0.71×）、所有绝对方差（0.67–0.74×）、16 采样的全部指标——都更差；偏差与固定采样同量级（相对偏差 ≤ 0.012%，|z| < 2，`rt_urban` 未重复该偏差表）。原因：Sobol 的固定采样已经很好地分层（方差 ∝ N^-1.4），把样本从平滑像元挪到噪声像元得不偿失，σ 只靠 4–16 个侦察样本估计也很噪。（`rt_urban` 与 legacy 采样器下的无偏版本没有重测；有偏的第一版在 legacy 上 64 采样相对方差好 1.6×，但带 +0.02% 至 +0.2% 的偏差，也不抵耗时。）
- 耗时（1024² 像元，best-of-5，含约 0.8 s 启动）：`rt_crop` 128 采样 固定 1.04 s、固定 160 采样 1.04 s、自适应 tile 1 1.46 s、tile 8 1.27 s；512 采样 固定 1.64 s、固定 640 采样 1.84 s、自适应 tile 1 4.56 s、tile 8 3.36 s；`rt_urban` 128 采样 0.85/0.95/1.28/1.16 s，512 采样 1.26/1.46/3.27/3.17 s。扣掉启动，自适应是同样总样本数固定采样的 2.4–3.5 倍（tile 1）与 2–3 倍（tile 8）：同一 warp 的线程样本数差别大，整体按最慢线程计时，再加两遍与读回。
- **结论**：等总样本数下没有一致的收益，等耗时下明显更差（耗时约 2.4–3.5×，方差最多好 1.3×），保持关闭（`control.adaptiveSampling` 缺省 `false`）。代码保留为可选实验（折叠后对常规路径零影响，输出缓冲只在开启时多分配两个平面）。如果将来要重新评估，值得先换分配目标（绝对方差 σ 而不是相对）、换成按 warp 分块并复用侦察样本（需解决无偏问题），或者改用逐像元的时间/负载均衡调度。
